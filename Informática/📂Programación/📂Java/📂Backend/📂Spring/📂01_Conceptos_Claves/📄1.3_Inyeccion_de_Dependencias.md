### 💡 La Explicación Sencilla

Esta es la consecuencia directa de la Inversión de Control. Si tú ya no haces los `new`.
¿cómo consigues usar un objeto dentro de otro ? 

## El Ejemplo de Código (El "Antes" y el "Después")

Vamos a ver un coche que necesita un motor.

## ❌ MODO ANTIGUO (Sin Spring - Tú eres el jefe)

Tú tienes que crear todo con `new`. Si cambias el motor, tienes que tocar el código del coche.

```Java
// Clase Motor
public class Motor {
    public void arrancar() { System.out.println("Brum brum"); }
}

// Clase Coche
public class Coche {

    private Motor motor;

    public Coche() {
        // TÚ tienes que crear el motor aquí. ¡Mal! Estás atado a él.
        this.motor = new Motor(); 
    }

    public void conducir() {
        motor.arrancar();
    }
}
```

## ✅ MODO SPRING (IoC + DI - Spring es el jefe)

Fíjate que desaparece la palabra `new`.

**Paso 1: IoC (El Almacén)** Le decimos a Spring: "Oye, gestiona tú el Motor". Usamos una etiqueta (en este caso `@Component` o `@Service`).

```Java
@Component // <--- ESTO ES IoC. Spring crea este objeto y lo guarda en su almacén.
public class Motor {
    public void arrancar() { System.out.println("Brum brum silencioso"); }
}
```

**Paso 2: DI (El Repartidor)** Le decimos a Spring: "Oye, inyéctame el motor aquí".

```Java
@Component // El coche también lo gestiona Spring
public class Coche {

    @Autowired // <--- ESTO ES DI. Spring busca el Motor en su almacén y lo conecta aquí.
    private Motor motor; 

    // ¡Fíjate! No hay constructor con 'new Motor()'. 
    // Spring lo ha metido mágicamente en la variable 'motor'.

    public void conducir() {
        motor.arrancar();
    }
}
```

### 💡 Resumen:

1. Pones **`@Component`** (o `@Service`/`@Repository`) en una clase -> **IoC**: Spring crea el objeto y se lo guarda.
    
2. Pones **`@Autowired`** en una variable -> **DI**: Spring busca ese objeto guardado en (beans) y te lo conecta.
