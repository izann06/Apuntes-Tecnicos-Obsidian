# 📜 Estructura Básica de un Script en Bash

## ¿Qué es un Script?

Un **script** es simplemente un archivo de texto plano que contiene una **secuencia de comandos** que se ejecutan uno tras otro, de arriba a abajo. En vez de escribir los comandos manualmente uno por uno en la terminal, los guardas en un archivo y los ejecutas todos de golpe.

> [!abstract] 📋 Analogía: La Lista de Instrucciones del Robot
> Imagina que tienes un robot de cocina al que puedes darle órdenes por voz, una a una: "abre la nevera", "saca los huevos", "enciende la sartén"... Pero si cada mañana le das las mismas 15 instrucciones, es mucho más eficiente escribir una **lista de instrucciones** en un papel y decirle: "sigue esta lista". Un script de Bash es esa lista de instrucciones para tu terminal.

## El Shebang: `#!/bin/bash`

La **primera línea** de todo script de Bash debe ser el **shebang** (también llamado hashbang):

```bash
#!/bin/bash
```

El shebang le dice al sistema operativo: **"usa el programa `/bin/bash` para interpretar este archivo"**. Sin el shebang, el sistema podría intentar ejecutar tu script con el shell por defecto del sistema (que podría no ser Bash).

```bash
#!/bin/bash
# ↑↑
# #! = el shebang (caracteres mágicos)
# /bin/bash = la ruta al intérprete que ejecutará el script
```

> [!tip] Otros shebangs comunes
> | Shebang | Intérprete |
> |---------|-----------|
> | `#!/bin/bash` | Bash (el estándar) |
> | `#!/bin/sh` | Shell POSIX genérico (más compatible pero menos funciones) |
> | `#!/usr/bin/env bash` | Busca bash en el PATH (más portable entre sistemas) |
> | `#!/usr/bin/python3` | Script de Python 3 |
> | `#!/usr/bin/env node` | Script de Node.js |

## Crear y Ejecutar tu Primer Script

### Paso 1: Crear el Archivo

```bash
# Crear el archivo con nano (o cualquier editor):
nano mi_script.sh
```

### Paso 2: Escribir el Contenido

```bash
#!/bin/bash
# Mi primer script de Bash
# Los comentarios empiezan con # y el sistema los ignora

echo "¡Hola, mundo!"
echo "Hoy es $(date)"
echo "Tu usuario es: $(whoami)"
echo "Estás en el directorio: $(pwd)"
echo "Tu sistema operativo es:"
uname -a
```

### Paso 3: Dar Permisos de Ejecución

```bash
# El script necesita permiso de ejecución para poder ejecutarse:
chmod +x mi_script.sh

# Verificar los permisos:
ls -l mi_script.sh
# -rwxr-xr-x 1 juan juan 234 sep 1 10:30 mi_script.sh
#  ↑ x = permiso de ejecución
```

Para entender los permisos en profundidad → [[03.2 - Modificación de Permisos (chmod)]]

### Paso 4: Ejecutar el Script

```bash
# Ejecutar con ./ (busca en el directorio actual):
./mi_script.sh

# Ejecutar especificando el intérprete (no necesita chmod +x):
bash mi_script.sh

# Ejecutar con ruta absoluta:
/home/juan/scripts/mi_script.sh
```

## Variables en Bash

### Variables Locales

Las variables en Bash se crean simplemente **asignándoles un valor**. No necesitas declarar tipos (no hay `int`, `string`, etc.).

```bash
#!/bin/bash

# Declarar variables (SIN espacios alrededor del =):
nombre="Juan"
edad=25
sistema_operativo="Linux"
directorio_actual=$(pwd)       # Ejecutar un comando y guardar su salida
fecha_actual=$(date +%F)       # Fecha en formato YYYY-MM-DD
numero_archivos=$(ls | wc -l)  # Contar archivos

# Usar variables (con $ delante):
echo "Hola, me llamo $nombre"
echo "Tengo $edad años"
echo "Uso $sistema_operativo"
echo "Estoy en: $directorio_actual"
echo "Hoy es: $fecha_actual"
echo "Hay $numero_archivos archivos aquí"

# Uso con llaves ${} (recomendado para evitar ambigüedades):
echo "El usuario ${nombre} tiene ${edad} años"
echo "Archivo: ${nombre}_backup.tar.gz"
# Sin llaves, Bash interpretaría $nombre_backup como UNA variable
```

> [!danger] ⚠️ Error #1 de principiantes: Espacios en la asignación
> ```bash
> # ❌ INCORRECTO (con espacios):
> nombre = "Juan"
> # bash: nombre: command not found
> 
> # ✅ CORRECTO (sin espacios):
> nombre="Juan"
> ```
> En Bash, los espacios alrededor del `=` hacen que Bash interprete `nombre` como un comando (no como una variable).

### Comillas Simples vs Dobles

```bash
nombre="Juan"

# Comillas dobles: LAS VARIABLES SE EXPANDEN
echo "Hola, $nombre"
# Hola, Juan

# Comillas simples: TODO es literal, NO se expande nada
echo 'Hola, $nombre'
# Hola, $nombre    ← Se imprime tal cual

# Backticks o $(): Ejecutar un comando y usar su salida
echo "La fecha es: $(date)"
echo "La fecha es: `date`"    # Equivalente pero estilo antiguo
```

## Variables de Entorno y `export`

### Variables Locales vs de Entorno

| Tipo | Alcance | Cómo crearla | ¿Los subprocesos la ven? |
|------|---------|-------------|-------------------------|
| **Variable local** | Solo la sesión/script actual | `MI_VAR="valor"` | ❌ No |
| **Variable de entorno** | La sesión actual + subprocesos | `export MI_VAR="valor"` | ✅ Sí |

```bash
# Variable LOCAL (solo visible en esta sesión):
SALUDO="Hola"
echo $SALUDO    # Hola
bash -c 'echo $SALUDO'    # (vacío, el subproceso no la ve)

# Variable de ENTORNO (visible para subprocesos):
export SALUDO="Hola"
echo $SALUDO    # Hola
bash -c 'echo $SALUDO'    # Hola (el subproceso SÍ la ve)

# Ver todas las variables de entorno:
env
# o:
printenv

# Variables de entorno del sistema más importantes:
echo $HOME       # /home/juan (tu carpeta home)
echo $USER       # juan (tu nombre de usuario)
echo $PATH       # /usr/local/bin:/usr/bin:/bin (dónde buscar comandos)
echo $SHELL      # /bin/bash (tu shell actual)
echo $LANG       # es_ES.UTF-8 (idioma del sistema)
echo $PWD        # /home/juan/proyectos (directorio actual)
echo $EDITOR     # nano o vim (editor por defecto)
```

## Persistir Variables y Alias: `~/.bashrc`

Los cambios que haces en la terminal son **temporales**: se pierden al cerrar la sesión. Para hacerlos permanentes, los escribes en el archivo `~/.bashrc`.

```bash
# Editar el archivo de configuración de Bash:
nano ~/.bashrc

# Añadir al final del archivo:

# ── Variables personalizadas ──
export EDITOR="nano"
export PROYECTOS="/home/juan/proyectos"
export HISTSIZE=10000

# ── Alias (atajos de comandos) ──
alias ll="ls -alh"
alias la="ls -la"
alias ..="cd .."
alias ...="cd ../.."
alias actualizar="sudo apt update && sudo apt upgrade -y"
alias puertos="sudo netstat -tlnp"
alias disco="df -h"
alias memoria="free -h"
alias buscar="grep -rn"

# ── PATH personalizado ──
export PATH="$HOME/.local/bin:$PATH"

# Guardar y salir de nano: Ctrl+O, Enter, Ctrl+X

# Aplicar los cambios SIN reiniciar la terminal:
source ~/.bashrc
# o el atajo:
. ~/.bashrc
```

> [!tip] `source` vs reiniciar terminal
> Después de editar `~/.bashrc`, necesitas "recargarlo" para que los cambios surtan efecto. Puedes:
> 1. Cerrar y abrir la terminal (los cambios se cargan al iniciar)
> 2. Ejecutar `source ~/.bashrc` (aplica los cambios instantáneamente)

## Ejemplo Completo: Script de Información del Sistema

```bash
#!/bin/bash
# ============================================
# Script: info_sistema.sh
# Descripción: Muestra un resumen del sistema
# Autor: Juan
# Fecha: 2026-09-01
# ============================================

# Variables
USUARIO=$(whoami)
HOSTNAME=$(hostname)
KERNEL=$(uname -r)
UPTIME=$(uptime -p)
MEMORIA=$(free -h | grep Mem | awk '{print $3 "/" $2}')
DISCO=$(df -h / | tail -1 | awk '{print $3 "/" $2 " (" $5 " usado)"}')
IP_LOCAL=$(hostname -I | awk '{print $1}')
PROCESOS=$(ps aux | wc -l)
FECHA=$(date "+%d/%m/%Y %H:%M:%S")

# Salida formateada
echo "============================================"
echo "        INFORMACIÓN DEL SISTEMA"
echo "============================================"
echo "  Usuario:    $USUARIO"
echo "  Hostname:   $HOSTNAME"
echo "  Kernel:     $KERNEL"
echo "  Uptime:     $UPTIME"
echo "  Memoria:    $MEMORIA"
echo "  Disco (/):  $DISCO"
echo "  IP Local:   $IP_LOCAL"
echo "  Procesos:   $PROCESOS"
echo "  Fecha:      $FECHA"
echo "============================================"
```

```bash
# Ejecutar:
chmod +x info_sistema.sh
./info_sistema.sh
# ============================================
#         INFORMACIÓN DEL SISTEMA
# ============================================
#   Usuario:    juan
#   Hostname:   mi-servidor
#   Kernel:     6.1.0-23-amd64
#   Uptime:     up 15 days, 3 hours, 22 minutes
#   Memoria:    3.2G/7.8G
#   Disco (/):  45G/100G (45% usado)
#   IP Local:   192.168.1.50
#   Procesos:   120
#   Fecha:      01/09/2026 10:30:45
# ============================================
```
