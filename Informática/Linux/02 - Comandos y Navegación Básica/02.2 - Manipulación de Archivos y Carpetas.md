# 📁 Manipulación de Archivos y Carpetas

## La Diferencia Fundamental: Linux es Case Sensitive

Antes de empezar con los comandos, hay una diferencia **crítica** entre Linux y Windows que debes grabar en tu memoria:

> [!danger] ⚠️ Linux DISTINGUE Mayúsculas de Minúsculas
> En Windows, `Archivo.txt`, `archivo.txt` y `ARCHIVO.TXT` son **el mismo archivo**. Windows es case-insensitive.
> 
> En Linux, cada combinación de mayúsculas y minúsculas crea un archivo **completamente diferente**:
> ```bash
> touch Archivo.txt archivo.txt ARCHIVO.TXT
> ls
> # Archivo.txt  ARCHIVO.TXT  archivo.txt    ← ¡Son TRES archivos distintos!
> ```
> 
> Esto también aplica a los comandos: `ls` funciona, pero `LS` o `Ls` dan error.

## `touch` — Crear Archivos Vacíos y Cambiar Fechas

El comando `touch` tiene dos funciones principales:
1. **Crear un archivo vacío** (si el archivo no existe)
2. **Actualizar la fecha de modificación** (si el archivo ya existe)

```bash
# Crear un archivo vacío:
touch notas.txt
ls -l notas.txt
# -rw-r--r-- 1 juan juan 0 sep  1 10:30 notas.txt
#                         ↑ Tamaño: 0 bytes (vacío)

# Crear múltiples archivos de golpe:
touch archivo1.txt archivo2.txt archivo3.txt

# Crear archivos con extensiones variadas:
touch script.sh datos.csv config.json readme.md

# Si el archivo YA existe, touch actualiza su fecha de modificación:
touch notas.txt
ls -l notas.txt
# -rw-r--r-- 1 juan juan 0 sep  1 10:35 notas.txt
#                                  ↑ La fecha cambió, el contenido NO

# Cambiar la fecha a una específica:
touch -t 202601011200 notas.txt   # 1 enero 2026, 12:00
```

> [!tip] ¿Por qué se llama "touch"?
> El nombre viene de "tocar" el archivo: cuando tocas un archivo, se actualiza su fecha de "última modificación" (como si le hubieras dado un toque). Si el archivo no existe, lo crea como efecto secundario. Es como tocar el timbre de una casa: si la casa existe, suena el timbre; si no existe, se construye una casa nueva (¡bueno, en el mundo Linux!).

## `mkdir` — Crear Directorios (Make Directory)

```bash
# Crear una carpeta:
mkdir proyectos

# Crear múltiples carpetas:
mkdir fotos videos documentos

# CREAR TODA UNA RUTA DE DIRECTORIOS ANIDADOS con -p (parents):
mkdir -p proyectos/web/frontend/css
# Crea TODAS las carpetas intermedias que no existan:
#   proyectos/
#   └── web/
#       └── frontend/
#           └── css/

# Sin -p, esto daría error si 'proyectos/web' no existe:
mkdir proyectos/web/frontend/css
# mkdir: cannot create directory 'proyectos/web/frontend/css':
# No such file or directory
```

> [!tip] El poder de `mkdir -p`
> La opción `-p` (parents) es una de las más útiles de Linux. Te permite crear toda una jerarquía de carpetas en un solo comando. Además, si alguna de las carpetas ya existe, no da error (simplemente la ignora). Es **idempotente**: puedes ejecutarlo múltiples veces sin problemas.

### Crear Estructuras Complejas con Llaves `{}`

```bash
# Crear múltiples subcarpetas con expansión de llaves:
mkdir -p proyecto/{src,tests,docs,config,scripts}
# Crea:
# proyecto/
# ├── src/
# ├── tests/
# ├── docs/
# ├── config/
# └── scripts/

# Estructura aún más compleja:
mkdir -p proyecto/{src/{main,lib},tests/{unit,integration},docs/{api,guides}}
# proyecto/
# ├── src/
# │   ├── main/
# │   └── lib/
# ├── tests/
# │   ├── unit/
# │   └── integration/
# └── docs/
#     ├── api/
#     └── guides/
```

## `rmdir` — Borrar Carpetas Vacías (Remove Directory)

`rmdir` **solo** puede borrar directorios que estén **completamente vacíos**. Si la carpeta tiene algo dentro (aunque sea un archivo oculto), no la borrará.

```bash
# Borrar una carpeta vacía:
rmdir carpeta_vacia

# Intentar borrar una carpeta con contenido:
rmdir carpeta_con_archivos
# rmdir: failed to remove 'carpeta_con_archivos': Directory not empty

# Borrar una jerarquía de carpetas vacías con -p:
rmdir -p proyecto/src/main
# Borra main, luego src, luego proyecto (si todos están vacíos)
```

> [!tip] En la práctica, `rmdir` se usa poco
> La mayoría de las veces usarás `rm -r` en lugar de `rmdir`, porque las carpetas rara vez están completamente vacías. `rmdir` es más una medida de seguridad: te obliga a vaciar la carpeta primero, asegurándote de que realmente quieres borrar todo su contenido.

## `rm` — Eliminar Archivos y Directorios (Remove)

El comando `rm` es el "destructor" de Linux. Borra archivos y, con las opciones adecuadas, carpetas enteras con todo su contenido.

```bash
# Borrar un archivo:
rm notas.txt

# Borrar múltiples archivos:
rm archivo1.txt archivo2.txt archivo3.txt

# Borrar con CONFIRMACIÓN interactiva (-i = interactive):
rm -i datos_importantes.txt
# rm: remove regular file 'datos_importantes.txt'? y

# Borrar una carpeta y TODO su contenido (-r = recursive):
rm -r carpeta_completa/
# Borra la carpeta y TODOS los archivos y subcarpetas dentro

# Forzar el borrado sin preguntar (-f = force):
rm -f archivo_protegido.txt
```

> [!danger] ⚠️ `rm -rf` — El Comando Más Peligroso de Linux
> La combinación `rm -rf` (**recursive** + **force**) borra todo sin preguntar, sin papelera de reciclaje, sin posibilidad de recuperación:
> 
> ```bash
> # ❌ NUNCA ejecutes esto como root:
> sudo rm -rf /          # Borra ABSOLUTAMENTE TODO el sistema operativo
> sudo rm -rf /*         # Igual de devastador
> sudo rm -rf ~          # Borra toda tu carpeta home
> rm -rf /home/*/        # Borra los homes de TODOS los usuarios
> ```
> 
> **No existe "papelera de reciclaje" en la terminal de Linux.** Cuando borras algo con `rm`, desaparece para siempre. No hay `Ctrl+Z`, no hay "deshacer". Por eso es fundamental:
> 1. **Siempre revisa** el comando antes de presionar Enter
> 2. **Usa `rm -i`** cuando tengas dudas (pide confirmación)
> 3. **Nunca copies y pegues** comandos `rm` de Internet sin entenderlos

### Buenas Prácticas con `rm`

```bash
# SIEMPRE usa -i para archivos importantes:
rm -ri directorio_importante/

# Primero lista lo que vas a borrar con ls:
ls carpeta_a_borrar/
# (revisar que no hay nada importante)
rm -r carpeta_a_borrar/

# Usar comodines con precaución (primero listar):
ls *.log          # Ver qué archivos .log hay
rm *.log          # Ahora sí, borrarlos

# Truco: Hacer un "simulacro" con echo antes de borrar:
echo rm -r /home/juan/descargas/*.tmp
# rm -r /home/juan/descargas/cache1.tmp /home/juan/descargas/cache2.tmp
# ↑ Esto NO borra nada, solo te muestra qué se borraría
```

## `cp` — Copiar Archivos y Directorios (Copy)

```bash
# Copiar un archivo:
cp original.txt copia.txt

# Copiar un archivo a otro directorio:
cp notas.txt /home/juan/backup/

# Copiar un archivo a otro directorio CON nuevo nombre:
cp notas.txt /home/juan/backup/notas_backup.txt

# Copiar un directorio completo (-r o -R = recursive):
cp -r proyecto/ proyecto_backup/

# Copiar manteniendo permisos, fechas y propietario (-a = archive):
cp -a proyecto/ proyecto_backup/

# Copiar con confirmación antes de sobrescribir (-i = interactive):
cp -i archivo.txt /destino/
# cp: overwrite '/destino/archivo.txt'? y

# Copiar múltiples archivos a un directorio:
cp archivo1.txt archivo2.txt archivo3.txt /destino/

# Copiar usando comodines (todos los .txt):
cp *.txt /home/juan/backup/
```

> [!tip] `-r` vs `-R` vs `-a`
> - `-r` y `-R` son equivalentes: copian directorios de forma recursiva (contenido completo)
> - `-a` (archive) es como `-r` pero **además** preserva los permisos, propietario, grupo y fechas originales. Es la mejor opción para hacer backups. Los permisos se explican en [[03.1 - Anatomía de los Permisos en Linux]].

## `mv` — Mover y Renombrar (Move)

El comando `mv` hace **dos cosas** dependiendo de cómo lo uses:
1. **Mover** un archivo/carpeta a otra ubicación
2. **Renombrar** un archivo/carpeta (moverlo al mismo directorio con otro nombre)

```bash
# RENOMBRAR un archivo (mover al mismo directorio con otro nombre):
mv viejo_nombre.txt nuevo_nombre.txt

# RENOMBRAR un directorio:
mv proyecto_viejo proyecto_nuevo

# MOVER un archivo a otro directorio:
mv notas.txt /home/juan/documentos/

# MOVER y RENOMBRAR a la vez:
mv notas.txt /home/juan/documentos/apuntes.txt

# MOVER un directorio completo:
mv proyecto/ /home/juan/backup/

# MOVER múltiples archivos a un directorio:
mv *.txt /home/juan/documentos/

# Mover con confirmación antes de sobrescribir:
mv -i archivo.txt /destino/
# mv: overwrite '/destino/archivo.txt'? y
```

> [!tip] La diferencia clave entre `cp` y `mv`
> - `cp` **duplica**: el archivo original permanece intacto y se crea una copia
> - `mv` **traslada**: el archivo original desaparece de su ubicación original y aparece en la nueva
> 
> Es como la diferencia entre **fotocopiar** un documento (cp) y **mover** un documento de una carpeta a otra (mv).

## Tabla Comparativa: Todos los Comandos de Manipulación

| Comando | Acción | Ejemplo | ¿Necesita `-r` para carpetas? |
|---------|--------|---------|------------------------------|
| `touch` | Crear archivo vacío | `touch nota.txt` | No aplica |
| `mkdir` | Crear directorio | `mkdir carpeta` | No (usa `-p` para anidados) |
| `rmdir` | Borrar directorio vacío | `rmdir carpeta` | No (solo vacíos) |
| `rm` | Borrar archivo | `rm nota.txt` | Sí: `rm -r carpeta` |
| `cp` | Copiar archivo | `cp a.txt b.txt` | Sí: `cp -r carpeta destino` |
| `mv` | Mover/Renombrar | `mv a.txt b.txt` | No (mueve carpetas directamente) |

## Caso Práctico: Organizar un Proyecto desde Cero

```bash
# 1. Crear la estructura del proyecto:
mkdir -p mi-app/{src/{components,utils},tests,docs,config}

# 2. Crear archivos iniciales:
touch mi-app/src/main.js
touch mi-app/src/components/{Header,Footer,Sidebar}.js
touch mi-app/src/utils/helpers.js
touch mi-app/tests/main.test.js
touch mi-app/docs/README.md
touch mi-app/config/{dev,prod}.json

# 3. Ver la estructura:
tree mi-app
# mi-app
# ├── config
# │   ├── dev.json
# │   └── prod.json
# ├── docs
# │   └── README.md
# ├── src
# │   ├── components
# │   │   ├── Footer.js
# │   │   ├── Header.js
# │   │   └── Sidebar.js
# │   ├── main.js
# │   └── utils
# │       └── helpers.js
# └── tests
#     └── main.test.js

# 4. Hacer un backup del proyecto:
cp -a mi-app/ mi-app-backup/

# 5. Renombrar un archivo:
mv mi-app/docs/README.md mi-app/docs/GUIA.md

# 6. Mover un archivo a otra carpeta:
mv mi-app/src/utils/helpers.js mi-app/src/components/

# 7. Limpiar archivos temporales:
rm -r mi-app/tests/
```
