# ⚙️ Gestión de Procesos, Señales y Control de Trabajos

## ¿Qué es un Proceso?

Un **proceso** es una **instancia de un programa en ejecución**. Cada vez que ejecutas un comando o abres una aplicación, el kernel crea un proceso con su propio espacio de memoria, variables de entorno y un identificador único.

> [!abstract] 🏃 Analogía: Receta vs Cocinar
> Un **programa** es como una **receta de cocina** escrita en un libro: es un archivo estático que describe los pasos a seguir. Un **proceso** es cuando **realmente estás cocinando** siguiendo esa receta: estás usando ingredientes reales (RAM), tiempo del cocinero (CPU), espacio en la encimera (memoria), etc. Puedes tener el mismo libro de recetas y cocinar el mismo plato tres veces simultáneamente: esos serían tres procesos diferentes del mismo programa.

### PID y PPID

| Identificador | Significado | Descripción |
|--------------|-------------|-------------|
| **PID** | Process ID | Número único que identifica a cada proceso |
| **PPID** | Parent Process ID | PID del proceso que creó (lanzó) este proceso |

```bash
# Ver el PID de tu terminal actual:
echo $$
# 12345

# Ver el PID del último proceso enviado al background:
echo $!

# Ver tu PID y PPID:
ps -p $$ -o pid,ppid,cmd
# PID   PPID CMD
# 12345 12340 -bash
```

## Monitoreo de Procesos

### `ps` — Snapshot de Procesos

`ps` (process status) muestra una **foto instantánea** de los procesos en ejecución.

```bash
# Ver solo TUS procesos:
ps
#   PID TTY          TIME CMD
# 12345 pts/0    00:00:00 bash
# 12367 pts/0    00:00:00 ps

# Ver TODOS los procesos del sistema (estilo BSD, la más usada):
ps aux
# USER  PID %CPU %MEM  VSZ   RSS TTY  STAT START  TIME COMMAND
# root    1  0.0  0.1 16982  9524 ?    Ss   ago15  0:12 /sbin/init
# root    2  0.0  0.0     0     0 ?    S    ago15  0:00 [kthreadd]
# juan  1234  0.5  2.1 34567 21234 pts/0 S+ 10:30  0:05 vim script.sh
# www   5678  0.1  1.5 56789 15234 ?    S   ago15  1:23 /usr/sbin/apache2

# Desglose de las columnas:
# USER   → Propietario del proceso
# PID    → ID del proceso
# %CPU   → Porcentaje de uso de CPU
# %MEM   → Porcentaje de uso de RAM
# VSZ    → Memoria virtual total (KB)
# RSS    → Memoria física real usada (KB)
# TTY    → Terminal asociada (? = sin terminal, es un servicio)
# STAT   → Estado del proceso
# START  → Cuándo se inició
# TIME   → Tiempo de CPU consumido
# COMMAND → El comando que se ejecutó

# Filtrar procesos con grep:
ps aux | grep apache
ps aux | grep -v grep | grep apache    # Excluir el propio grep

# Ver procesos en formato de árbol (quién creó a quién):
ps auxf
# o:
pstree
```

#### Estados de los Procesos (STAT)

| Estado | Significado |
|--------|-------------|
| `R` | **Running** — Ejecutándose o listo para ejecutarse |
| `S` | **Sleeping** — Durmiendo, esperando un evento (E/S, señal) |
| `D` | **Disk sleep** — Esperando E/S de disco (no se puede interrumpir) |
| `T` | **Stopped** — Detenido (por `Ctrl+Z` o señal STOP) |
| `Z` | **Zombie** — Terminó pero su padre no recogió su código de salida |
| `+` | Proceso en primer plano (foreground) |
| `s` | Líder de sesión |
| `<` | Alta prioridad |
| `N` | Baja prioridad (nice) |

### `top` — Monitor en Tiempo Real

```bash
top
# top - 10:30:45 up 15 days,  3:22,  2 users,  load average: 0.15, 0.10, 0.05
# Tasks: 195 total,   1 running, 194 sleeping,   0 stopped,   0 zombie
# %Cpu(s):  2.3 us,  0.5 sy,  0.0 ni, 97.0 id,  0.1 wa,  0.0 hi,  0.1 si
# MiB Mem:   7976.4 total,   2045.2 free,   3210.1 used,   2721.1 buff/cache
# MiB Swap:  2048.0 total,   2048.0 free,      0.0 used.   4456.3 avail Mem
#
#   PID USER      PR  NI    VIRT    RES    SHR S  %CPU  %MEM     TIME+ COMMAND
#  1234 juan      20   0  345678  21234  15678 R   5.3   2.1   0:05.23 firefox
#  5678 www-data  20   0   56789  15234  10234 S   1.2   1.5   1:23.45 apache2
#   456 root      20   0   12345   5678   3456 S   0.3   0.5   0:12.34 systemd

# Teclas interactivas dentro de top:
# q     → Salir
# M     → Ordenar por uso de MEMORIA
# P     → Ordenar por uso de CPU
# k     → Matar un proceso (pide PID y señal)
# u     → Filtrar por usuario
# h     → Ayuda
```

### `htop` — Monitor Visual Mejorado

```bash
# Instalar htop:
sudo apt install htop

# Ejecutar:
htop
# Muestra un monitor con barras de colores para CPU y RAM,
# navegación con flechas, y opciones interactivas con teclas F1-F10

# Teclas principales:
# F3 o /    → Buscar proceso
# F4        → Filtrar
# F5        → Vista de árbol
# F6        → Ordenar por columna
# F9        → Enviar señal (kill)
# F10 o q   → Salir
# Espacio   → Marcar/desmarcar proceso
```

> [!tip] `htop` es `top` con esteroides
> Si vas a elegir uno, usa `htop`. Es más visual, más intuitivo y más fácil de usar. Muestra barras de colores para CPU y RAM, puedes navegar con las flechas, y tiene atajos de teclado más intuitivos.

## Control de Trabajos (Jobs)

### Ejecutar en Segundo Plano: `&`

```bash
# Ejecutar un proceso en segundo plano con & al final:
sleep 60 &
# [1] 12345    ← [número de trabajo] PID

# El comando se ejecuta mientras tú sigues trabajando en la terminal

# Ejemplo real: Descargar un archivo grande en background:
wget https://ejemplo.com/archivo_grande.iso &

# Ejemplo: Iniciar un servidor en background:
python3 -m http.server 8080 &
```

### Suspender y Reanudar Procesos

```bash
# Ejecutar un proceso normalmente (primer plano):
ping google.com
# (Está ejecutándose, tu terminal está bloqueada)

# Presiona Ctrl+Z para SUSPENDER el proceso:
# ^Z
# [1]+  Stopped    ping google.com

# Ver los trabajos suspendidos y en background:
jobs
# [1]+  Stopped    ping google.com
# [2]-  Running    wget https://ejemplo.com/archivo.iso &

# Reanudar en PRIMER plano (fg = foreground):
fg %1
# ping google.com continúa en primer plano

# Reanudar en SEGUNDO plano (bg = background):
bg %1
# ping google.com continúa en segundo plano

# El % seguido del número es el ID del trabajo (job ID)
# fg sin número trae el último trabajo
```

### Tabla de Control de Trabajos

| Acción | Comando | Descripción |
|--------|---------|-------------|
| Ejecutar en background | `comando &` | Inicia el proceso en segundo plano |
| Suspender proceso | `Ctrl + Z` | Pausa el proceso en primer plano |
| Listar trabajos | `jobs` | Muestra trabajos activos y suspendidos |
| Traer a primer plano | `fg %N` | Reanuda el trabajo N en foreground |
| Enviar a segundo plano | `bg %N` | Reanuda el trabajo N en background |

## Señales y el Comando `kill`

Las **señales** son mensajes que el kernel envía a los procesos para controlarlos. El comando `kill` envía señales a procesos específicos usando su PID.

```bash
# Sintaxis:
kill -SEÑAL PID

# Enviar la señal por defecto (TERM = terminar ordenadamente):
kill 12345

# Enviar una señal específica por número:
kill -9 12345

# Enviar una señal específica por nombre:
kill -KILL 12345
kill -SIGKILL 12345
```

### Tabla de Señales Críticas

| Señal | Número | Nombre | Atajo de Teclado | Descripción |
|-------|--------|--------|-------------------|-------------|
| **HUP** | 1 | SIGHUP | — | **Reiniciar** configuración (demonios como Apache/Nginx releen sus configs) |
| **INT** | 2 | SIGINT | `Ctrl + C` | **Interrumpir** el proceso (terminación educada) |
| **KILL** | 9 | SIGKILL | — | **Matar** el proceso a la fuerza. No se puede ignorar ni capturar. Último recurso |
| **TERM** | 15 | SIGTERM | — | **Terminar** ordenadamente (por defecto). El proceso puede limpiar antes de salir |
| **CONT** | 18 | SIGCONT | — | **Continuar** un proceso detenido (reanudarlo) |
| **STOP** | 19 | SIGSTOP | `Ctrl + Z` | **Detener/pausar** el proceso. No se puede ignorar |

```bash
# Ejemplo: Reiniciar Apache sin apagarlo (relee configuración):
sudo kill -1 $(pgrep apache2)
# o:
sudo kill -HUP $(pgrep apache2)

# Terminar un proceso de forma ordenada (por defecto):
kill 12345
# o explícitamente:
kill -15 12345

# Forzar el cierre de un proceso que no responde:
kill -9 12345
```

> [!danger] ⚠️ `kill -9` es el último recurso
> La señal `-9` (SIGKILL) mata el proceso **inmediatamente** sin darle oportunidad de:
> - Guardar datos pendientes
> - Cerrar archivos abiertos
> - Limpiar archivos temporales
> - Liberar recursos
>
> Siempre intenta primero con `kill PID` (señal 15/TERM) y espera unos segundos. Solo usa `kill -9` si el proceso realmente no responde.

### `killall` — Matar por Nombre

```bash
# Matar TODOS los procesos con ese nombre:
killall firefox
# Cierra todas las ventanas de Firefox

killall -9 chrome
# Fuerza el cierre de todos los procesos de Chrome

# Matar procesos de un usuario específico:
sudo killall -u maria
# Mata TODOS los procesos del usuario maria
```

## Apagado del Sistema

```bash
# Apagar inmediatamente:
sudo poweroff
# o:
sudo shutdown -P now

# Reiniciar:
sudo reboot
# o:
sudo shutdown -r now

# Apagar en 10 minutos con aviso a los usuarios:
sudo shutdown -P +10 "El servidor se apagará en 10 minutos"

# Reiniciar a una hora específica:
sudo shutdown -r 23:00 "Reinicio programado a las 11 PM"

# Cancelar un apagado/reinicio programado:
sudo shutdown -c "Apagado cancelado"

# Detener la CPU (halt) sin apagar la fuente:
sudo halt
```

| Comando | Acción |
|---------|--------|
| `poweroff` | Apaga el sistema y la fuente de alimentación |
| `reboot` | Reinicia el sistema |
| `halt` | Detiene la CPU (no apaga la fuente) |
| `shutdown -P now` | Apaga inmediatamente |
| `shutdown -r now` | Reinicia inmediatamente |
| `shutdown -P +N` | Apaga en N minutos |
| `shutdown -c` | Cancela un shutdown programado |
