# 🛡️ Seguridad por Defecto (UMask y Permisos Especiales)

## Parte 1: La Máscara UMask

### ¿Qué es UMask?

Cada vez que creas un archivo o directorio en Linux, el sistema le asigna unos **permisos por defecto**. Pero, ¿quién decide cuáles son esos permisos? La respuesta es la **umask** (user file-creation mask).

La umask es una "máscara" que **resta permisos** de los máximos iniciales para determinar los permisos finales de cada archivo o directorio nuevo.

> [!abstract] 🎭 Analogía: La Máscara de Pintura
> Imagina que vas a pintar una pared de blanco (permisos máximos). Pero antes de pintar, pones una **máscara/plantilla** sobre la pared que **bloquea** ciertas zonas. Las zonas bloqueadas no se pintan (permisos eliminados). Las zonas descubiertas sí se pintan (permisos permitidos). La umask es esa plantilla: define qué permisos se **bloquean** por defecto.

### ¿Cómo Funciona la Resta?

Los permisos máximos iniciales son:
- **Directorios**: `777` (rwxrwxrwx) — todos los permisos posibles
- **Archivos**: `666` (rw-rw-rw-) — lectura y escritura para todos (sin ejecución por seguridad)

La umask se **resta** de estos máximos:

```
Permisos finales = Permisos máximos - umask

Para directorios: 777 - umask = permisos del nuevo directorio
Para archivos:    666 - umask = permisos del nuevo archivo
```

### Ver y Entender tu UMask Actual

```bash
# Ver la umask actual:
umask
# 0022    (el primer 0 es para permisos especiales, nos interesan los 3 últimos)

# Ver la umask en formato simbólico:
umask -S
# u=rwx,g=rx,o=rx
```

### Ejemplos de Cálculo

Con la umask por defecto `0022`:

```
DIRECTORIOS:    777 - 022 = 755 (rwxr-xr-x)
                 ↓                ↓
                Máximo           Resultado: Dueño todo, resto leer/entrar

ARCHIVOS:       666 - 022 = 644 (rw-r--r--)
                 ↓                ↓
                Máximo           Resultado: Dueño leer/escribir, resto solo leer
```

```bash
# Verificar en la práctica:
umask
# 0022

mkdir nueva_carpeta
ls -ld nueva_carpeta
# drwxr-xr-x   ← 755 (777 - 022)

touch nuevo_archivo.txt
ls -l nuevo_archivo.txt
# -rw-r--r--   ← 644 (666 - 022)
```

### Tabla de UMasks Comunes

| UMask | Permisos de Directorios | Permisos de Archivos | Nivel de Seguridad |
|-------|------------------------|---------------------|-------------------|
| `000` | 777 (rwxrwxrwx) | 666 (rw-rw-rw-) | 🔴 Mínima — Todo abierto |
| `002` | 775 (rwxrwxr-x) | 664 (rw-rw-r--) | 🟡 Colaborativa — Grupo puede escribir |
| `022` | 755 (rwxr-xr-x) | 644 (rw-r--r--) | 🟢 **Por defecto** — Equilibrada |
| `027` | 750 (rwxr-x---) | 640 (rw-r-----) | 🔵 Restrictiva — Otros sin acceso |
| `077` | 700 (rwx------) | 600 (rw-------) | 🔒 Máxima — Solo el dueño |

### Cambiar la UMask

```bash
# Cambiar la umask TEMPORALMENTE (solo para esta sesión de terminal):
umask 077
touch archivo_privado.txt
ls -l archivo_privado.txt
# -rw-------   ← 600 (666 - 077) ¡Totalmente privado!

mkdir carpeta_privada
ls -ld carpeta_privada
# drwx------   ← 700 (777 - 077)

# Cambiar la umask PERMANENTEMENTE (para todas las sesiones futuras):
echo "umask 027" >> ~/.bashrc
# La próxima vez que abras una terminal, la umask será 027
```

> [!warning] Cuidado con umask en scripts y Cron
> La umask de una tarea programada con Cron → [[05.6 - Programación de Tareas con Cron (Crontab)]] puede ser diferente a la de tu sesión interactiva. Si tu script crea archivos que necesitan permisos específicos, establece la umask explícitamente al inicio del script:
> ```bash
> #!/bin/bash
> umask 022    # Asegurar permisos 644 para archivos, 755 para directorios
> # ... resto del script
> ```

## Parte 2: Permisos Especiales

Además de los permisos estándar `rwx`, Linux tiene **tres permisos especiales** que añaden funcionalidades de seguridad avanzadas. Se representan con un **cuarto dígito** al inicio del número octal.

```
chmod  4  7  5  5   archivo
       │  │  │  │
       │  │  │  └── Otros
       │  │  └── Grupo
       │  └── Usuario
       └── Permiso Especial (4=SUID, 2=SGID, 1=Sticky)
```

---

### SetUID (SUID) — Octal 4000

El bit **SetUID** hace que cuando **cualquier usuario** ejecute un archivo, se ejecute con los permisos del **propietario del archivo** (en vez de con los permisos del usuario que lo ejecuta).

> [!abstract] 🎭 Analogía: La Tarjeta VIP Temporal
> Imagina que en un hotel, solo el gerente puede abrir la caja fuerte. Pero hay un botón especial en la recepción que, cuando cualquier empleado lo presiona, le da **temporalmente** los poderes del gerente para abrir la caja fuerte, solo durante esa operación específica. Cuando termina, vuelve a ser un empleado normal. Eso es el SUID: un programa te da temporalmente los poderes de su propietario.

#### El Ejemplo Clásico: El Comando `passwd`

```bash
# El archivo /etc/shadow contiene las contraseñas cifradas:
ls -l /etc/shadow
# -rw-r----- 1 root shadow 1234 sep 1 10:00 /etc/shadow
# Solo root puede leer/escribir este archivo

# Pero CUALQUIER usuario puede cambiar su propia contraseña:
passwd
# ¿Cómo es posible si /etc/shadow solo lo puede modificar root?

# La respuesta está en el SUID del comando passwd:
ls -l /usr/bin/passwd
# -rwsr-xr-x 1 root root 68208 sep 1 10:00 /usr/bin/passwd
#    ↑
#    s en lugar de x = SUID ACTIVADO
```

Cuando ejecutas `passwd`, el programa se ejecuta **temporalmente como root** (porque root es el propietario), lo que le permite escribir en `/etc/shadow`. Cuando termina, vuelves a ser un usuario normal.

#### Cómo Identificar y Configurar el SUID

```bash
# La 's' minúscula aparece en la posición de ejecución del USUARIO:
# -rwsr-xr-x   ← SUID activado (s = SUID + ejecución)
# -rwSr-xr-x   ← SUID activado pero SIN ejecución (S mayúscula = alerta)

# Activar SUID:
chmod u+s programa
chmod 4755 programa

# Desactivar SUID:
chmod u-s programa

# Buscar TODOS los archivos con SUID en el sistema:
find / -perm -4000 -type f 2>/dev/null
# /usr/bin/passwd
# /usr/bin/sudo
# /usr/bin/chfn
# /usr/bin/newgrp
```

> [!danger] ⚠️ SUID es un Riesgo de Seguridad
> Un archivo con SUID ejecuta siempre con los permisos de su dueño. Si un programa con SUID perteneciente a root tiene una vulnerabilidad, un atacante podría explotarla para obtener **acceso root** al sistema. Por eso:
> - **Nunca** pongas SUID en scripts de Bash (es inherentemente inseguro)
> - Audita regularmente los archivos con SUID: `find / -perm -4000 -type f`
> - Solo los programas del sistema deberían tener SUID

### SetGID (SGID) — Octal 2000

El bit **SetGID** tiene dos comportamientos diferentes:

- **En archivos ejecutables**: El programa se ejecuta con los permisos del **grupo** del archivo (similar al SUID pero para el grupo).
- **En directorios**: Los archivos creados dentro del directorio **heredan el grupo del directorio** padre, en vez del grupo del usuario que los crea.

> [!abstract] 📁 Analogía: La Carpeta del Departamento
> Imagina un departamento de marketing en una empresa. Todos los documentos que se dejan en la carpeta del departamento de marketing automáticamente se etiquetan como "propiedad de marketing", sin importar quién los haya puesto ahí. Eso es el SGID en directorios: todo lo que se crea dentro hereda el grupo del directorio.

#### SGID en Directorios (Uso Más Común)

```bash
# Crear un directorio de equipo:
sudo mkdir /proyecto/compartido
sudo chown :developers /proyecto/compartido

# SIN SGID: Cada archivo tiene el grupo del usuario que lo crea
touch /proyecto/compartido/archivo_juan.txt
ls -l /proyecto/compartido/archivo_juan.txt
# -rw-r--r-- 1 juan juan 0 ...   ← Grupo: juan (NO developers)

# CON SGID: Los archivos heredan el grupo del directorio
sudo chmod g+s /proyecto/compartido
# o con octal:
sudo chmod 2775 /proyecto/compartido

ls -ld /proyecto/compartido
# drwxrwsr-x 2 root developers 4096 ...
#        ↑
#        s en la posición de ejecución del GRUPO = SGID

touch /proyecto/compartido/archivo_nuevo.txt
ls -l /proyecto/compartido/archivo_nuevo.txt
# -rw-r--r-- 1 juan developers 0 ...   ← ¡Grupo: developers! (heredado)
```

#### Cómo Identificar y Configurar el SGID

```bash
# La 's' aparece en la posición de ejecución del GRUPO:
# drwxrwsr-x   ← SGID activado en directorio

# Activar SGID:
chmod g+s directorio/
chmod 2755 directorio/

# Desactivar SGID:
chmod g-s directorio/

# Buscar directorios con SGID:
find / -perm -2000 -type d 2>/dev/null
```

### Sticky Bit — Octal 1000

El **Sticky Bit** es un permiso especial para **directorios compartidos**. Cuando está activado, los archivos dentro del directorio **solo pueden ser borrados por su propietario** (o por root), incluso si otros usuarios tienen permisos de escritura en el directorio.

> [!abstract] 🗑️ Analogía: La Pizarra de Anuncios del Trabajo
> Imagina una pizarra de anuncios en la oficina donde cualquier empleado puede poner sus notas. Sin Sticky Bit, cualquiera podría quitar las notas de los demás. Con Sticky Bit, cada persona **solo puede quitar sus propias notas**. Las notas de los demás están protegidas, aunque la pizarra sea "pública".

#### El Ejemplo Clásico: `/tmp`

```bash
# /tmp es el directorio temporal donde TODOS pueden escribir:
ls -ld /tmp
# drwxrwxrwt 15 root root 4096 sep 1 10:00 /tmp
#          ↑
#          t en la posición de ejecución de OTROS = Sticky Bit

# Cualquier usuario puede crear archivos en /tmp:
touch /tmp/mi_archivo.txt

# Pero otro usuario NO puede borrar TU archivo:
# (como usuario 'maria'):
rm /tmp/mi_archivo.txt
# rm: cannot remove '/tmp/mi_archivo.txt': Operation not permitted
# ¡Solo 'juan' (el creador) o root pueden borrarlo!
```

#### Cómo Configurar el Sticky Bit

```bash
# Activar Sticky Bit:
chmod +t directorio_compartido/
chmod 1777 directorio_compartido/

# Desactivar Sticky Bit:
chmod -t directorio_compartido/

# Verificar:
ls -ld directorio_compartido/
# drwxrwxrwt   ← La 't' al final indica Sticky Bit activo
```

## Tabla Resumen de Permisos Especiales

| Permiso | Octal | Dónde aparece | Letra | Aplica a | Efecto |
|---------|-------|--------------|-------|----------|--------|
| **SUID** | 4000 | Posición `x` del usuario | `s` | Archivos ejecutables | Se ejecuta con permisos del propietario |
| **SGID** | 2000 | Posición `x` del grupo | `s` | Archivos y directorios | Archivos: ejecuta como el grupo. Directorios: hereda grupo |
| **Sticky** | 1000 | Posición `x` de otros | `t` | Directorios | Solo el dueño puede borrar sus archivos |

### Indicadores Visuales

| Carácter | Significado |
|----------|-------------|
| `s` (minúscula) | SUID/SGID activado **Y** permiso de ejecución presente |
| `S` (mayúscula) | SUID/SGID activado **PERO** sin permiso de ejecución ⚠️ |
| `t` (minúscula) | Sticky Bit activado **Y** permiso de ejecución presente |
| `T` (mayúscula) | Sticky Bit activado **PERO** sin permiso de ejecución ⚠️ |

> [!warning] `S` y `T` mayúsculas son anomalías
> Si ves una `S` o `T` mayúscula, significa que el permiso especial está activo pero **falta el permiso de ejecución**. Esto generalmente no tiene sentido práctico y puede indicar una configuración incorrecta. Un SUID sin permiso de ejecución es como tener una llave VIP para una puerta que no puede abrirse.
