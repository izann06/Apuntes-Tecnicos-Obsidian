# 👥 Administración de Usuarios, Grupos y Propiedades

## Los Archivos de Almacenamiento del Sistema

Linux guarda toda la información sobre usuarios y grupos en tres archivos de texto plano dentro de `/etc/`. Entender estos archivos es fundamental para cualquier administrador de sistemas.

### `/etc/passwd` — La Base de Datos de Usuarios

A pesar de su nombre, este archivo **no contiene contraseñas** (las contenía en el pasado, ahora están en `/etc/shadow`). Contiene la información básica de cada usuario del sistema.

```bash
# Ver el contenido:
cat /etc/passwd

# Formato de cada línea:
# usuario:x:UID:GID:info:home:shell
# juan:x:1000:1000:Juan García:/home/juan:/bin/bash

# Desglose:
# juan      → Nombre de usuario (login)
# x         → Marcador de contraseña (la real está en /etc/shadow)
# 1000      → UID (User ID) — Identificador numérico único
# 1000      → GID (Group ID) — Grupo principal del usuario
# Juan García → Campo GECOS (nombre completo, info de contacto)
# /home/juan  → Directorio home del usuario
# /bin/bash   → Shell por defecto del usuario

# Ver solo tu línea:
grep "^$(whoami):" /etc/passwd

# Contar cuántos usuarios hay en el sistema:
wc -l /etc/passwd
# Muchos serán usuarios del sistema (no personas reales)

# Ver solo usuarios "humanos" (UID >= 1000):
awk -F: '$3 >= 1000 && $3 < 65534 {print $1}' /etc/passwd
```

> [!tip] UIDs importantes
> - **UID 0** = root (superusuario) — SIEMPRE es 0
> - **UID 1-999** = Usuarios del sistema (servicios como apache, mysql, postgres)
> - **UID 1000+** = Usuarios humanos normales
> - **UID 65534** = nobody (usuario sin privilegios para procesos inseguros)

### `/etc/shadow` — Las Contraseñas Cifradas

Este archivo contiene las contraseñas **cifradas** (hasheadas) de todos los usuarios. Solo root puede leerlo.

```bash
# Intentar leer sin ser root:
cat /etc/shadow
# cat: /etc/shadow: Permission denied

# Leer como root:
sudo cat /etc/shadow
# juan:$6$rAnDoMsAlT$hashLargoAquí:19600:0:99999:7:::

# Formato:
# usuario:hash_contraseña:último_cambio:mín_días:máx_días:aviso:inact:expire

# Ver los permisos del archivo:
ls -l /etc/shadow
# -rw-r----- 1 root shadow 1234 sep 1 10:00 /etc/shadow
```

> [!danger] ⚠️ Nunca edites `/etc/shadow` directamente
> Siempre usa los comandos `passwd`, `useradd`, `usermod`, etc. para gestionar usuarios y contraseñas. Editar manualmente estos archivos puede dejar el sistema en un estado inconsistente o dejarte sin acceso.

### `/etc/group` — Los Grupos del Sistema

```bash
cat /etc/group
# Formato: nombre_grupo:x:GID:miembros
# developers:x:1001:juan,maria,pedro
# sudo:x:27:juan
# docker:x:999:juan

# Ver los grupos a los que perteneces:
groups
# juan sudo developers docker

# Ver los grupos de otro usuario:
groups maria
# maria developers www-data

# Ver info detallada de tu usuario:
id
# uid=1000(juan) gid=1000(juan) groups=1000(juan),27(sudo),1001(developers)

id maria
# uid=1001(maria) gid=1001(maria) groups=1001(maria),1001(developers)
```

## Cambiar de Usuario: `su` vs `sudo`

### `su` — Cambiar de Usuario (Switch User)

El comando `su` te permite **convertirte temporalmente en otro usuario**.

```bash
# Cambiar al usuario maria (mantiene tu entorno):
su maria
# Pide la contraseña de MARIA
whoami
# maria

# Cambiar al usuario maria CARGANDO su perfil completo (su -):
su - maria
# Pide la contraseña de MARIA
# Carga su .bashrc, .profile, variables de entorno, etc.
pwd
# /home/maria  (te lleva a su home)

# Cambiar a root:
su -
# Pide la contraseña de ROOT
whoami
# root

# Volver a tu usuario original:
exit
```

> [!warning] Diferencia crítica: `su` vs `su -`
> - `su maria` → Te conviertes en maria pero **mantienes TU entorno** (variables, directorio actual, PATH). Es como ponerte una máscara de maria pero seguir en tu oficina.
> - `su - maria` → Te conviertes en maria y **cargas TODO su entorno** como si hicieras login desde cero. Es como mudarte literalmente a la oficina de maria.

### `sudo` — Ejecutar como Administrador (Super User Do)

El comando `sudo` te permite ejecutar **un solo comando** con privilegios de root, sin tener que cambiar de usuario. Es mucho más seguro que usar `su` para convertirte en root.

```bash
# Instalar un programa (necesita privilegios de root):
sudo apt install htop
# Pide TU contraseña (no la de root)

# Editar un archivo de configuración del sistema:
sudo nano /etc/hostname

# Reiniciar un servicio:
sudo systemctl restart apache2

# Ver quién puede usar sudo:
sudo cat /etc/sudoers

# Ejecutar un comando como OTRO usuario específico:
sudo -u maria touch /home/maria/archivo_de_juan.txt
```

> [!tip] ¿Por qué `sudo` es mejor que `su`?
> 1. **No necesitas saber la contraseña de root** (usas la tuya)
> 2. **Cada acción queda registrada** en `/var/log/auth.log`
> 3. **Privilegios temporales**: solo el comando específico se ejecuta como root
> 4. **Control granular**: puedes configurar exactamente qué comandos puede ejecutar cada usuario con `sudo`

### Tabla Comparativa: `su` vs `sudo`

| Aspecto | `su` | `sudo` |
|---------|------|--------|
| **¿Qué hace?** | Cambiar completamente de usuario | Ejecutar un solo comando como root |
| **Contraseña requerida** | La del usuario destino | La **tuya** |
| **Duración** | Hasta que escribas `exit` | Solo ese comando |
| **Registro en logs** | Mínimo | Cada comando se registra |
| **Riesgo** | Alto (sesión root abierta) | Bajo (comando puntual) |
| **Configuración** | Conocer la contraseña | Estar en `/etc/sudoers` o grupo `sudo` |
| **Uso recomendado** | Cuando necesitas hacer MUCHAS tareas como otro usuario | Para tareas puntuales de administración |

### El Archivo `/etc/sudoers`

```bash
# NUNCA edites /etc/sudoers con nano o vim directamente.
# Usa SIEMPRE visudo (valida la sintaxis antes de guardar):
sudo visudo

# Contenido típico:
# root    ALL=(ALL:ALL) ALL
# %sudo   ALL=(ALL:ALL) ALL
# juan    ALL=(ALL) NOPASSWD: /usr/bin/apt

# Desglose:
# root    ALL=(ALL:ALL) ALL
# │       │    │    │    │
# Quién   Desde qué  Como qué  Qué comandos
#         hosts     usuario
```

## Gestión de Cuentas de Usuario

### `adduser` — Crear Usuarios (Forma Interactiva)

```bash
# Crear un nuevo usuario (interactivo, pregunta datos):
sudo adduser maria
# Adding user 'maria' ...
# Adding new group 'maria' (1001) ...
# Adding new user 'maria' (1001) with group 'maria' ...
# Creating home directory '/home/maria' ...
# Copying files from '/etc/skel' ...
# New password: ****
# Retype new password: ****
# Full Name []: María López
# Room Number []:
# Work Phone []:
# Home Phone []:
# Other []:
# Is the information correct? [Y/n] y

# useradd es la versión NO interactiva (más para scripts):
sudo useradd -m -s /bin/bash -G developers pedro
# -m → Crear el directorio home
# -s → Shell por defecto
# -G → Grupos adicionales
```

### `usermod` — Modificar Usuarios

```bash
# Añadir un usuario a un grupo ADICIONAL (sin quitarlo de los actuales):
sudo usermod -aG sudo maria
# -a = append (AÑADIR, no reemplazar)
# -G = grupo(s) adicional(es)

# ¡CUIDADO sin -a! Esto REEMPLAZA todos los grupos:
# sudo usermod -G sudo maria  ← ¡Quita a maria de TODOS los demás grupos!

# Cambiar el shell de un usuario:
sudo usermod -s /bin/zsh maria

# Cambiar el nombre de login:
sudo usermod -l nuevo_nombre viejo_nombre

# Bloquear una cuenta (desactivar login):
sudo usermod -L maria

# Desbloquear una cuenta:
sudo usermod -U maria
```

### Borrar Usuarios

```bash
# Borrar un usuario (mantiene su carpeta home):
sudo deluser maria

# Borrar un usuario Y su carpeta home:
sudo deluser --remove-home maria

# Borrar un usuario de un grupo específico:
sudo deluser maria developers
```

## Gestión de Propiedad: `chown`

El comando `chown` (**ch**ange **own**er) cambia el **propietario** y/o el **grupo** de un archivo o directorio.

```bash
# Cambiar solo el PROPIETARIO:
sudo chown maria archivo.txt
# Antes: -rw-r--r-- 1 juan  juan  → Después: -rw-r--r-- 1 maria juan

# Cambiar solo el GRUPO:
sudo chown :developers archivo.txt
# Antes: -rw-r--r-- 1 juan  juan  → Después: -rw-r--r-- 1 juan  developers

# Cambiar PROPIETARIO y GRUPO a la vez:
sudo chown maria:developers archivo.txt
# Antes: -rw-r--r-- 1 juan  juan  → Después: -rw-r--r-- 1 maria developers

# Cambiar recursivamente (directorio y todo su contenido):
sudo chown -R maria:developers /proyecto/
# Cambia dueño Y grupo de la carpeta y TODOS los archivos dentro

# Caso real: Servidor web Apache
sudo chown -R www-data:www-data /var/www/html/
# Apache necesita ser dueño de los archivos web para servirlos
```

### `chgrp` — Cambiar Solo el Grupo

```bash
# Cambiar el grupo de un archivo:
sudo chgrp developers archivo.txt

# Cambiar recursivamente:
sudo chgrp -R developers proyecto/
```

## Caso Práctico: Configurar un Entorno de Equipo

```bash
# 1. Crear el grupo del equipo:
sudo groupadd equipo-web

# 2. Crear los usuarios del equipo:
sudo adduser ana
sudo adduser carlos

# 3. Añadir usuarios al grupo (sin quitarlos de otros grupos):
sudo usermod -aG equipo-web ana
sudo usermod -aG equipo-web carlos

# 4. Crear la carpeta compartida del proyecto:
sudo mkdir -p /proyectos/web-app

# 5. Asignar propietario y grupo:
sudo chown root:equipo-web /proyectos/web-app

# 6. Permisos: dueño y grupo todo, otros nada + SGID para herencia:
sudo chmod 2770 /proyectos/web-app
# SGID → Los nuevos archivos heredarán el grupo 'equipo-web'
# Ver [[03.3 - Seguridad por Defecto (UMask y Permisos Especiales)]]

# 7. Verificar:
ls -ld /proyectos/web-app
# drwxrws--- 2 root equipo-web 4096 sep 1 10:00 /proyectos/web-app

# 8. Ahora ana y carlos pueden crear archivos compartidos:
su - ana
touch /proyectos/web-app/index.html
ls -l /proyectos/web-app/index.html
# -rw-r--r-- 1 ana equipo-web 0 sep 1 10:00 index.html
# ↑ ¡El grupo es equipo-web, no ana! (gracias al SGID)
```
