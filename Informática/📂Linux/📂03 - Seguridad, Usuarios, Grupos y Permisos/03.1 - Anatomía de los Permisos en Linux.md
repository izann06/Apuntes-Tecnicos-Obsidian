# 🔐 Anatomía de los Permisos en Linux

## ¿Por Qué Linux Necesita Permisos?

Linux fue diseñado desde el principio como un sistema **multiusuario**: muchas personas pueden trabajar en el mismo servidor al mismo tiempo. Esto significa que necesita un sistema robusto para **proteger a los usuarios entre sí**. Sin permisos, cualquier usuario podría leer las contraseñas de otro, borrar los archivos de un compañero, o ejecutar programas maliciosos con privilegios de administrador.

> [!abstract] 🏢 Analogía: El Edificio de Oficinas con Tarjetas de Acceso
> Imagina un edificio de oficinas donde trabajan 50 personas. Cada empleado tiene una **tarjeta de acceso** que define exactamente a qué salas puede entrar:
> - **Tu oficina** (permisos de usuario): Puedes leer documentos, escribir informes y ejecutar programas.
> - **La oficina de tu equipo** (permisos de grupo): Tu equipo de marketing puede acceder a la sala de reuniones de marketing, pero no a la del departamento legal.
> - **Las zonas comunes** (permisos de otros): El comedor, el baño y el vestíbulo son accesibles para todos.
> - **El despacho del CEO** (root): Solo una persona tiene la llave maestra que abre todas las puertas.
>
> Los permisos de Linux funcionan exactamente así: cada archivo tiene definido quién puede leerlo, quién puede modificarlo y quién puede ejecutarlo.

## Los 10 Caracteres: Descifrando la Cadena de Permisos

Cuando ejecutas `ls -l`, cada archivo muestra una cadena de 10 caracteres al inicio que define todos sus permisos:

```bash
ls -l
# -rw-r--r-- 1 juan developers 4096 sep  1 10:30 informe.txt
# drwxr-xr-x 3 juan developers 4096 sep  1 09:15 proyectos/
# lrwxrwxrwx 1 juan developers   24 sep  1 08:00 enlace -> /var/log/syslog
# -rwxr-xr-x 1 juan developers  512 sep  1 10:00 script.sh
```

### Desglose Visual

```
- r w x r - x r - -
│ ├─┬─┤ ├─┬─┤ ├─┬─┤
│   │     │     │
│   │     │     └── OTROS (o) — "El resto del mundo"
│   │     │         Cualquier usuario que no sea el propietario
│   │     │         ni pertenezca al grupo
│   │     │
│   │     └── GRUPO (g) — "Tu equipo"
│   │         Los usuarios que pertenecen al grupo asignado
│   │         al archivo
│   │
│   └── USUARIO PROPIETARIO (u) — "El dueño"
│       El usuario que creó el archivo (o al que se le
│       asignó la propiedad)
│
└── TIPO DE ARCHIVO
    -  → Archivo regular
    d  → Directorio (carpeta)
    l  → Enlace simbólico (acceso directo)
    b  → Dispositivo de bloque (disco)
    c  → Dispositivo de carácter (teclado, terminal)
    p  → Pipe (tubería con nombre)
    s  → Socket
```

## El Primer Carácter: Tipo de Archivo

| Carácter | Tipo | Descripción | Ejemplo |
|----------|------|-------------|---------|
| `-` | Archivo regular | Un archivo normal (texto, imagen, ejecutable...) | `-rw-r--r-- notas.txt` |
| `d` | Directorio | Una carpeta | `drwxr-xr-x proyectos/` |
| `l` | Enlace simbólico | Un "acceso directo" que apunta a otro archivo | `lrwxrwxrwx enlace -> /var/log` |
| `b` | Dispositivo de bloque | Un dispositivo de almacenamiento (disco duro) | `brw-rw---- /dev/sda` |
| `c` | Dispositivo de carácter | Dispositivos de E/S carácter por carácter | `crw-rw-rw- /dev/null` |

---

## Los Tres Bloques de Permisos: u, g, o

Después del tipo de archivo, los 9 caracteres restantes se dividen en **tres bloques de tres caracteres** cada uno:

```
  u (user)     g (group)    o (others)
 ┌─────────┐  ┌─────────┐  ┌─────────┐
 │ r  w  x │  │ r  -  x │  │ r  -  - │
 └─────────┘  └─────────┘  └─────────┘
   Dueño        Grupo         Otros
```

| Bloque | Letra | ¿A quién aplica? | Ejemplo |
|--------|-------|-------------------|---------|
| **Usuario** (user) | `u` | El propietario del archivo | Si `juan` es dueño, estos permisos aplican solo a `juan` |
| **Grupo** (group) | `g` | Los miembros del grupo asignado | Si el grupo es `developers`, aplica a todos los `developers` |
| **Otros** (others) | `o` | Todos los demás usuarios | Cualquier usuario que no sea el dueño ni del grupo |

---

## Las Tres Letras: r, w, x

Cada bloque puede contener tres permisos posibles:

### Significado en ARCHIVOS

| Permiso | Letra | Valor Octal | Significado en Archivos |
|---------|-------|-------------|------------------------|
| **Lectura** | `r` | 4 | Puedes **ver/leer** el contenido del archivo (`cat`, `less`, `head`) |
| **Escritura** | `w` | 2 | Puedes **modificar/editar** el contenido del archivo (`nano`, `vim`, `echo >>`) |
| **Ejecución** | `x` | 1 | Puedes **ejecutar** el archivo como un programa o script (`./script.sh`) |
| Sin permiso | `-` | 0 | No tienes ese permiso |

### Significado en DIRECTORIOS

> [!warning] ¡Los permisos significan cosas DIFERENTES en directorios!
> Este es uno de los conceptos que más confunde a los principiantes. Las mismas letras `r`, `w`, `x` tienen significados completamente distintos cuando aplican a un directorio:

| Permiso | En un ARCHIVO | En un DIRECTORIO |
|---------|--------------|-----------------|
| **r** (lectura) | Leer el contenido del archivo | **Listar** el contenido de la carpeta (`ls`) |
| **w** (escritura) | Modificar el contenido del archivo | **Crear y borrar** archivos dentro de la carpeta |
| **x** (ejecución) | Ejecutar el archivo como programa | **Entrar** en la carpeta (`cd`) y acceder a su contenido |

```bash
# Ejemplo: Un directorio con r pero sin x
# Puedes VER los nombres de los archivos (ls), pero NO puedes
# entrar en la carpeta (cd) ni acceder a los archivos dentro.

# Un directorio con x pero sin r
# Puedes ENTRAR en la carpeta (cd) y acceder a archivos si
# conoces su nombre, pero NO puedes listar qué hay dentro (ls).
```

> [!abstract] 🔑 Analogía: La Puerta del Almacén
> Piensa en un directorio como un almacén con una puerta:
> - **r** (lectura) = Tienes una **ventana** para ver los estantes y leer los nombres de las cajas → puedes hacer `ls`
> - **w** (escritura) = Tienes un **pasillo de acceso** para meter y sacar cajas → puedes crear y borrar archivos
> - **x** (ejecución) = Tienes la **llave de la puerta** para entrar físicamente → puedes hacer `cd`
> 
> Sin la llave (`x`), puedes mirar por la ventana (`r`) pero no entrar. Sin la ventana (`r`), puedes entrar (`x`) pero no sabes qué hay dentro a menos que sepas el nombre exacto de lo que buscas.

## Ejemplos Prácticos de Lectura de Permisos

### Ejemplo 1: `drwxr-xr-x`

```
d  rwx  r-x  r-x
│   │    │    │
│   │    │    └── Otros: r-x → pueden listar y entrar, NO crear/borrar
│   │    └── Grupo: r-x → pueden listar y entrar, NO crear/borrar
│   └── Usuario: rwx → puede listar, crear/borrar y entrar (control total)
└── Tipo: d = directorio
```

**Traducción humana**: Es una carpeta. El dueño tiene control total. El grupo y los demás pueden ver y entrar, pero no modificar nada dentro.

### Ejemplo 2: `-rw-r--r--`

```
-  rw-  r--  r--
│   │    │    │
│   │    │    └── Otros: r-- → solo pueden LEER el archivo
│   │    └── Grupo: r-- → solo pueden LEER el archivo
│   └── Usuario: rw- → puede LEER y ESCRIBIR (pero NO ejecutar)
└── Tipo: - = archivo regular
```

**Traducción humana**: Es un archivo normal. El dueño puede leerlo y editarlo. Todos los demás solo pueden leerlo. Nadie puede ejecutarlo.

### Ejemplo 3: `-rwxr-xr-x`

```
-  rwx  r-x  r-x
│   │    │    │
│   │    │    └── Otros: r-x → pueden leer y ejecutar
│   │    └── Grupo: r-x → pueden leer y ejecutar
│   └── Usuario: rwx → control total (leer, escribir, ejecutar)
└── Tipo: - = archivo regular
```

**Traducción humana**: Es un archivo ejecutable (como un script o programa). El dueño tiene control total. Todos pueden ejecutarlo y leerlo, pero solo el dueño puede modificarlo. Es el permiso típico de los comandos del sistema como `ls`, `cat`, `grep`, etc.

### Ejemplo 4: `-rw-------`

```
-  rw-  ---  ---
│   │    │    │
│   │    │    └── Otros: --- → SIN ningún acceso
│   │    └── Grupo: --- → SIN ningún acceso
│   └── Usuario: rw- → puede leer y escribir
└── Tipo: - = archivo regular
```

**Traducción humana**: Archivo completamente privado. Solo el dueño puede leerlo y editarlo. Nadie más puede ni siquiera ver su contenido. Es el permiso típico de archivos como `~/.ssh/id_rsa` (claves privadas SSH) o `/etc/shadow` (contraseñas cifradas).

## Tabla de Permisos Comunes

| Permisos | Octal | ¿Quién puede qué? | Uso Típico |
|----------|-------|--------------------|-----------|
| `-rwxrwxrwx` | 777 | **Todos** pueden todo | ⚠️ Inseguro, evitar |
| `-rwxr-xr-x` | 755 | Dueño: todo. Resto: leer y ejecutar | Programas, scripts públicos |
| `-rw-r--r--` | 644 | Dueño: leer/escribir. Resto: solo leer | Archivos normales, configs públicas |
| `-rw-rw-r--` | 664 | Dueño y grupo: leer/escribir. Otros: leer | Archivos de trabajo en equipo |
| `-rw-------` | 600 | Solo dueño: leer/escribir | Claves SSH, archivos privados |
| `-rwx------` | 700 | Solo dueño: control total | Scripts privados, carpetas personales |
| `drwxr-xr-x` | 755 | Dueño: todo. Resto: listar y entrar | Carpetas de proyectos |
| `drwx------` | 700 | Solo dueño: todo | Carpeta home privada |
| `drwxrwxrwt` | 1777 | Todos pueden crear, solo dueño borra | `/tmp` → [[03.3 - Seguridad por Defecto (UMask y Permisos Especiales)]] |

## Cómo Ver los Permisos en la Práctica

```bash
# Ver permisos de archivos:
ls -l
# -rw-r--r-- 1 juan developers 4096 sep 1 10:30 informe.txt

# Ver permisos de un directorio (no su contenido):
ls -ld /home/juan
# drwxr-xr-x 15 juan juan 4096 sep 1 09:00 /home/juan

# Ver permisos en formato octal (con stat):
stat -c "%a %n" informe.txt
# 644 informe.txt

stat -c "%a %n" /home/juan
# 755 /home/juan

# Ver permisos detallados:
stat informe.txt
# File: informe.txt
# Size: 4096       Blocks: 8     IO Block: 4096   regular file
# Access: (0644/-rw-r--r--)  Uid: (1000/juan)  Gid: (1000/developers)
# Access: 2026-09-01 10:30:00
# Modify: 2026-09-01 10:30:00
# Change: 2026-09-01 10:30:00
```

Para aprender a **cambiar** estos permisos, continúa en → [[03.2 - Modificación de Permisos (chmod)]].
