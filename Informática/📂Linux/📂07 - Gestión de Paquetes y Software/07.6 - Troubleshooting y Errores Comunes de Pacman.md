# 07.6 — Troubleshooting y Errores Comunes de Pacman

Si algo sale mal instalando programas en CachyOS, es muy raro tener que reinstalar el sistema operativo. Casi siempre se soluciona ejecutando una de estas tres técnicas de mantenimiento de Pacman.

## 🧹 1. Limpiar la Caché de Pacman (`-Sc`)

Cada vez que descargas un programa o una actualización, Pacman es previsor y guarda el archivo comprimido original en el directorio `/var/cache/pacman/pkg/`. Lo hace "por si acaso" la nueva actualización tiene un fallo grave y quieres hacer *downgrade* a la versión anterior que te funcionaba.

**El Problema:** Si nunca prestas atención a esto y no lo borras, en unos meses esta carpeta irá acumulando versiones viejas y puede llegar a ocupar 30 GB o 40 GB de tu disco duro para nada.

**Solución:** Borrar las versiones antiguas.
```bash
# Borra todos los paquetes cacheados excepto los que tienes actualmente instalados
sudo pacman -Sc
```

## 💥 2. Solucionar Descargas Corruptas (`Error reading fd 8`)

**El Escenario:** Estás descargando un programa grande, y de repente el Wi-Fi se corta, se va la luz, o cancelas el proceso apretando `Ctrl+C` compulsivamente.
**El Error:** Al intentar instalar otra vez, te sale un error parecido a `Error reading fd 8`, `invalid or corrupted package`, o pacman se queda colgado infinitamente diciendo que está analizando la integridad del paquete.

**Por qué ocurre:** Al cancelarse la descarga de forma brusca, se quedó guardado un archivo "roto" (corrupto) a medio descargar en la carpeta temporal. Pacman es un poco tonto aquí: intenta usar ese archivo roto en vez de empezar de cero, y se estrella.

**Solución:** Tienes que ir a la carpeta de descargas de pacman y borrar manualmente esos archivos temporales rotos para desbloquear el gestor.
```bash
# Elimina los archivos atascados que quedaron a medias de descarga (.part)
sudo rm -rf /var/cache/pacman/pkg/*.part
```
*(Lo que tú tuviste que usar, `sudo rm -rf /var/cache/pacman/pkg/download-*`, sirve exactamente para el mismo propósito: limpiar los archivos residuales de descargas truncadas).*

## 🪞 3. Refrescar los Mirrors (Espejos) Lentos o Caídos

Los repositorios de Linux (los servidores donde están los archivos) no están en un solo ordenador central (se quemaría). Están copiados de forma idéntica en cientos de servidores por todo el mundo, donados por universidades e instituciones. Estos se llaman **Mirrors** (Espejos).

**El Problema:** Estás intentando descargar o actualizar algo, y de repente va a 20 KB/s en pleno 2024, o te da errores continuos de timeout y conexión. Esto significa que el *espejo* que tu PC ha elegido para conectarse hoy está muy lejos (ej: en China), está saturado, o se ha desconectado.

**La Solución en CachyOS:** Necesitas que tu PC haga una carrera o "ping" contra todos los servidores del mundo para ver cuáles le responden más rápido en este momento, y crear una lista nueva priorizando los 5 o 10 mejores. En CachyOS, esto suele estar automatizado, pero puedes forzarlo si notas lentitud.

```bash
# Herramienta de CachyOS que evalúa y reinstala la lista de espejos más rápidos para tu conexión
cachyos-rate-mirrors
```

> [!warning] OBLIGATORIO tras actualizar espejos
> Inmediatamente después de actualizar o tocar la lista de mirrors, los catálogos se resetean. **Siempre** debes forzar una sincronización para que el sistema descargue las bases de datos de los nuevos espejos rápidos que acabas de configurar:
> ```bash
> sudo pacman -Syyu
> ```
