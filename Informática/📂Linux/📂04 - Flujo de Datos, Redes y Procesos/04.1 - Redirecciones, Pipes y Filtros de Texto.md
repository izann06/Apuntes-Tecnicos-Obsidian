# 🔀 Redirecciones, Pipes y Filtros de Texto

## Los Tres Canales de Datos: stdin, stdout, stderr

Cada programa en Linux tiene **tres canales de comunicación** abiertos por defecto, como tres tuberías por las que fluyen los datos:

```
                    ┌──────────────┐
  TECLADO ─────────►│              │──────────► PANTALLA
  (stdin)           │   PROGRAMA   │           (stdout)
  Descriptor: 0     │              │
                    │              │──────────► PANTALLA
                    └──────────────┘           (stderr)
                                              Descriptor: 2
```

| Canal | Nombre | Descriptor | Dirección | ¿Qué transporta? |
|-------|--------|-----------|-----------|-------------------|
| **stdin** | Entrada estándar | 0 | Hacia el programa ← | Los datos que el programa recibe (teclado o archivo) |
| **stdout** | Salida estándar | 1 | Desde el programa → | Los resultados normales del programa |
| **stderr** | Error estándar | 2 | Desde el programa → | Los mensajes de error del programa |

> [!abstract] 🏭 Analogía: La Fábrica con Tres Cintas Transportadoras
> Imagina un programa como una **fábrica**:
> - **stdin** (entrada) es la cinta transportadora por la que entran las **materias primas** (datos de entrada)
> - **stdout** (salida) es la cinta por la que salen los **productos terminados** (resultados)
> - **stderr** (errores) es una cinta separada por la que salen los **productos defectuosos** (errores)
>
> Las redirecciones te permiten **cambiar hacia dónde apuntan estas cintas**: en vez de que la salida vaya a la pantalla, puedes enviarla a un archivo. En vez de que la entrada venga del teclado, puedes alimentar el programa con un archivo.

## Redirecciones de Salida: `>` y `>>`

### `>` — Sobrescribir Salida a un Archivo

El operador `>` toma la salida estándar (stdout) de un comando y la **guarda en un archivo**, sobrescribiendo su contenido anterior.

```bash
# Guardar la lista de archivos en un archivo:
ls -la > listado.txt
# La salida de ls NO aparece en pantalla, se guarda en listado.txt

# Ver el contenido guardado:
cat listado.txt

# Guardar la fecha actual:
date > fecha_actual.txt

# Guardar información del sistema:
uname -a > info_sistema.txt

# Crear un archivo con contenido directamente:
echo "Hola Mundo" > saludo.txt

# ¡CUIDADO! > SOBRESCRIBE el archivo completo:
echo "Primera línea" > notas.txt
echo "Segunda línea" > notas.txt
cat notas.txt
# Segunda línea    ← ¡La primera se perdió!
```

### `>>` — Añadir al Final (Append)

El operador `>>` **añade** la salida al final del archivo sin borrar el contenido existente.

```bash
# Añadir líneas sin borrar las anteriores:
echo "Línea 1" > log.txt       # Crea/sobrescribe
echo "Línea 2" >> log.txt      # Añade al final
echo "Línea 3" >> log.txt      # Añade al final
cat log.txt
# Línea 1
# Línea 2
# Línea 3

# Caso real: Registrar acciones en un log:
echo "$(date): Backup iniciado" >> /var/log/mi_backup.log
# Ejecutar backup...
echo "$(date): Backup completado" >> /var/log/mi_backup.log
```

## Redirección de Entrada: `<`

El operador `<` alimenta un programa con datos **desde un archivo** en vez de desde el teclado.

```bash
# Contar las líneas de un archivo:
wc -l < /etc/passwd
# 45

# Ordenar el contenido de un archivo:
sort < nombres.txt

# Enviar un email (ejemplo conceptual):
mail usuario@ejemplo.com < mensaje.txt
```

## Redirección de Errores: `2>`

El descriptor `2` corresponde a stderr. Puedes redirigir solo los errores:

```bash
# Redirigir errores a un archivo:
find / -name "archivo.txt" 2> errores.log
# Los resultados van a pantalla, los errores "Permission denied" al archivo

# Descartar errores al "agujero negro" /dev/null:
find / -name "passwd" 2>/dev/null
# Solo muestra resultados, los errores desaparecen silenciosamente

# Guardar salida Y errores en archivos separados:
comando > salida.txt 2> errores.txt

# Guardar salida Y errores en el MISMO archivo:
comando > todo.txt 2>&1
# 2>&1 significa: "envía stderr (2) al mismo sitio que stdout (1)"

# Forma moderna equivalente:
comando &> todo.txt
```

### Tabla Resumen de Redirecciones

| Operador | Acción | Ejemplo |
|----------|--------|---------|
| `>` | Redirigir stdout a archivo (sobrescribe) | `ls > lista.txt` |
| `>>` | Redirigir stdout a archivo (añade al final) | `echo "log" >> app.log` |
| `<` | Redirigir archivo a stdin | `wc -l < datos.txt` |
| `2>` | Redirigir stderr a archivo | `find / -name x 2> err.log` |
| `2>/dev/null` | Descartar errores | `cmd 2>/dev/null` |
| `> archivo 2>&1` | stdout Y stderr al mismo archivo | `cmd > todo.txt 2>&1` |
| `&>` | stdout Y stderr al mismo archivo (moderno) | `cmd &> todo.txt` |

## La Barra de Pipe `|` — Conectar Comandos

El pipe `|` es una de las herramientas más poderosas de Linux. Conecta la **salida estándar** (stdout) de un comando con la **entrada estándar** (stdin) del siguiente, creando una **cadena de procesamiento**.

```
Comando1  ──stdout──►  |  ──stdin──►  Comando2  ──stdout──►  |  ──stdin──►  Comando3
```

> [!abstract] 🔧 Analogía: La Cadena de Montaje
> Imagina una fábrica de coches con varias estaciones de trabajo en línea. La primera estación hace el chasis, la segunda instala el motor, la tercera pone las ruedas, la cuarta pinta el coche. Cada estación **recibe** el resultado de la anterior y **produce** algo para la siguiente. El pipe `|` es la cinta transportadora que conecta una estación con la siguiente.

```bash
# Ejemplo básico: Listar archivos y contar cuántos hay:
ls | wc -l
# 15    (hay 15 archivos/carpetas)

# Listar procesos y filtrar solo los de Apache:
ps aux | grep apache

# Ver los usuarios del sistema ordenados:
cat /etc/passwd | cut -d: -f1 | sort

# Encontrar los 5 archivos más grandes:
du -sh * | sort -rh | head -5

# Ver quién está conectado al sistema y contar:
who | wc -l

# Encadenar múltiples pipes:
cat /var/log/syslog | grep "error" | sort | uniq -c | sort -rn | head -10
# 1. Lee el log del sistema
# 2. Filtra líneas con "error"
# 3. Ordena alfabéticamente
# 4. Cuenta ocurrencias únicas
# 5. Ordena por cantidad (más errores primero)
# 6. Muestra solo los 10 más frecuentes
```

## Comandos de Filtro: Tu Caja de Herramientas de Texto

### `grep` — Buscar y Filtrar Patrones

`grep` (**G**lobal **R**egular **E**xpression **P**rint) busca líneas que coinciden con un patrón de texto.

```bash
# Buscar una palabra en un archivo:
grep "error" /var/log/syslog
# Muestra todas las líneas que contienen "error"

# Búsqueda insensible a mayúsculas (-i):
grep -i "error" /var/log/syslog
# Encuentra "error", "Error", "ERROR", "eRrOr"...

# Excluir líneas que coinciden (-v = inverse):
grep -v "comentario" config.txt
# Muestra todas las líneas EXCEPTO las que contienen "comentario"

# Mostrar el número de línea (-n):
grep -n "TODO" codigo.py
# 15: # TODO: Implementar validación
# 42: # TODO: Añadir tests

# Contar cuántas coincidencias hay (-c):
grep -c "error" /var/log/syslog
# 23

# Buscar recursivamente en todos los archivos de una carpeta (-r):
grep -r "password" /etc/
# /etc/pam.d/common-password: ...
# /etc/login.defs: ...

# Buscar una palabra EXACTA (-w = whole word):
grep -w "red" archivo.txt
# Encuentra "red" pero NO "redirigir" ni "predeterminado"

# Mostrar contexto (líneas antes/después):
grep -A 3 "error" log.txt    # 3 líneas Después (After)
grep -B 2 "error" log.txt    # 2 líneas Antes (Before)
grep -C 2 "error" log.txt    # 2 líneas antes Y después (Context)
```

### `wc` — Contar (Word Count)

```bash
# Contar líneas, palabras y bytes:
wc archivo.txt
# 100  500  3200  archivo.txt
#  │    │     │
# Líneas Palabras Bytes

# Solo contar LÍNEAS (-l):
wc -l /etc/passwd
# 45 /etc/passwd

# Solo contar PALABRAS (-w):
wc -w ensayo.txt
# 2500 ensayo.txt

# Solo contar CARACTERES/BYTES (-c):
wc -c archivo.txt
# 3200 archivo.txt

# Contar líneas de la salida de otro comando (con pipe):
ls | wc -l
# 15  (archivos en el directorio actual)

ps aux | wc -l
# 120  (procesos en ejecución)
```

### `sort` — Ordenar

```bash
# Ordenar líneas alfabéticamente:
sort nombres.txt

# Orden inverso (-r = reverse):
sort -r nombres.txt

# Ordenar numéricamente (-n):
sort -n numeros.txt
# Sin -n: 1, 10, 11, 2, 20, 3 (orden de texto)
# Con -n: 1, 2, 3, 10, 11, 20 (orden numérico real)

# Ordenar por tamaño legible (-h = human-numeric):
du -sh * | sort -rh
# 1.5G  videos/
# 250M  fotos/
# 10K   notas.txt

# Eliminar duplicados al ordenar (-u = unique):
sort -u nombres.txt

# Ordenar por una columna específica (-k):
# Ordenar /etc/passwd por UID (campo 3, separador ':'):
sort -t: -k3 -n /etc/passwd
```

### `head` y `tail` — Principio y Final

```bash
# Ver las primeras 10 líneas (por defecto):
head /etc/passwd

# Ver las primeras N líneas:
head -n 5 /etc/passwd    # Primeras 5 líneas
head -5 /etc/passwd      # Atajo equivalente

# Ver las últimas 10 líneas (por defecto):
tail /etc/passwd

# Ver las últimas N líneas:
tail -n 20 /var/log/syslog

# SEGUIMIENTO EN TIEMPO REAL (-f = follow):
tail -f /var/log/syslog
# ¡Se queda abierto mostrando nuevas líneas según aparecen!
# Perfecto para monitorizar logs en vivo
# Presiona Ctrl+C para salir
```

> [!tip] `tail -f` es ESENCIAL para sysadmins
> El comando `tail -f` te permite ver un archivo de log **en tiempo real**. Cada vez que se añade una línea nueva al archivo, aparece automáticamente en tu terminal. Es como ver las noticias en directo pero de tu servidor. Lo usarás constantemente para:
> - Monitorear logs de aplicaciones web: `tail -f /var/log/apache2/access.log`
> - Depurar errores: `tail -f /var/log/syslog | grep error`
> - Vigilar intentos de acceso: `tail -f /var/log/auth.log`

### Tabla Comparativa: `head` vs `tail`

| Aspecto | `head` | `tail` |
|---------|--------|--------|
| **Muestra** | Las **primeras** líneas | Las **últimas** líneas |
| **Por defecto** | 10 primeras | 10 últimas |
| **Especificar N** | `head -n 5` | `tail -n 5` |
| **Tiempo real** | ❌ No tiene | ✅ `tail -f` (follow) |
| **Uso típico** | Ver cabeceras de CSV, primeras líneas de código | Monitorizar logs, ver últimos eventos |

## Ejemplo Práctico Completo: Pipeline de Análisis

```bash
# Pregunta: ¿Cuáles son las 5 IPs que más intentos de login fallidos tienen?

cat /var/log/auth.log | grep "Failed password" | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head -5

# Paso a paso:
# 1. cat → Lee el archivo de log de autenticación
# 2. grep → Filtra solo las líneas de contraseñas fallidas
# 3. awk  → Extrae la dirección IP de cada línea
# 4. sort → Ordena las IPs alfabéticamente (necesario para uniq)
# 5. uniq -c → Cuenta las IPs repetidas
# 6. sort -rn → Ordena por cantidad (más intentos primero)
# 7. head -5 → Muestra solo las 5 primeras

# Resultado:
#   423 192.168.1.100
#   198 10.0.0.55
#    87 172.16.0.3
#    45 192.168.1.200
#    12 10.0.0.1
```
