# 🌐 Configuración de Redes en Linux

## Diagnóstico: Conocer tu Red

### `ifconfig` — La Herramienta Clásica

`ifconfig` (interface configuration) es el comando clásico para ver y configurar las interfaces de red. Aunque está siendo reemplazado por `ip`, sigue siendo muy usado.

```bash
# Instalar si no está disponible:
sudo apt install net-tools

# Ver TODAS las interfaces de red activas:
ifconfig
# eth0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
#         inet 192.168.1.50  netmask 255.255.255.0  broadcast 192.168.1.255
#         inet6 fe80::1  prefixlen 64  scopeid 0x20<link>
#         ether 08:00:27:ab:cd:ef  txqueuelen 1000  (Ethernet)
#         RX packets 12345  bytes 6789012 (6.7 MB)
#         TX packets 9876  bytes 5432109 (5.4 MB)
#
# lo: flags=73<UP,LOOPBACK,RUNNING>  mtu 65536
#         inet 127.0.0.1  netmask 255.0.0.0
#         loop  txqueuelen 1000  (Local Loopback)

# Ver una interfaz específica:
ifconfig eth0
```

#### Desglose de la Salida

```
eth0                                    ← Nombre de la interfaz
├── inet 192.168.1.50                   ← Tu dirección IPv4
├── netmask 255.255.255.0              ← Máscara de subred
├── broadcast 192.168.1.255            ← Dirección de broadcast
├── inet6 fe80::1                      ← Tu dirección IPv6
├── ether 08:00:27:ab:cd:ef            ← Dirección MAC (hardware)
├── RX packets / bytes                  ← Datos RECIBIDOS
└── TX packets / bytes                  ← Datos TRANSMITIDOS
```

### `ip a` — La Herramienta Moderna

`ip` (de iproute2) es el reemplazo moderno de `ifconfig`, más potente y flexible.

```bash
# Ver todas las interfaces de red:
ip a
# o la forma completa:
ip address show

# Ver solo una interfaz:
ip a show eth0

# Ver solo direcciones IPv4:
ip -4 a

# Ver solo direcciones IPv6:
ip -6 a

# Ver el estado de las interfaces (UP/DOWN):
ip link show
```

### Interfaces de Red Comunes

| Interfaz | Descripción | IP Típica |
|----------|-------------|----------|
| `lo` | **Loopback** — La máquina se habla a sí misma | `127.0.0.1` (siempre) |
| `eth0` | Primera tarjeta Ethernet (cable) | `192.168.x.x` o `10.x.x.x` |
| `wlan0` | Primera tarjeta WiFi inalámbrica | `192.168.x.x` |
| `ens33` | Ethernet (nomenclatura moderna en VMs) | `192.168.x.x` |
| `docker0` | Interfaz de red de Docker | `172.17.0.1` |
| `virbr0` | Bridge virtual de KVM/libvirt | `192.168.122.1` |

> [!tip] ¿Qué es el Loopback (127.0.0.1)?
> La interfaz **loopback** (`lo`) es una interfaz virtual que permite al equipo **comunicarse consigo mismo**. La dirección `127.0.0.1` (o `localhost`) siempre apunta a tu propia máquina. Es útil para probar servicios localmente: si levantas un servidor web en tu máquina, puedes acceder a él en `http://127.0.0.1` o `http://localhost` sin necesidad de red.

## Diagnóstico de Conectividad

### `ping` — Comprobar Conexión

```bash
# Comprobar si hay conexión con un servidor:
ping google.com
# PING google.com (142.250.200.46): 56 data bytes
# 64 bytes from 142.250.200.46: icmp_seq=0 ttl=118 time=12.3 ms
# 64 bytes from 142.250.200.46: icmp_seq=1 ttl=118 time=11.8 ms
# Presiona Ctrl+C para detener

# Enviar solo N pings (-c = count):
ping -c 4 google.com
# Envía solo 4 pings y se detiene

# Ping a una IP local:
ping 192.168.1.1    # Router/gateway

# Ping a localhost (verificar que la red funciona):
ping 127.0.0.1

# Ping con intervalo personalizado (-i = interval en segundos):
ping -i 2 google.com    # Un ping cada 2 segundos
```

### `route` — Ver la Puerta de Enlace

```bash
# Ver la tabla de rutas (gateways):
route
# o la versión moderna:
ip route

# Salida típica:
# default via 192.168.1.1 dev eth0
# 192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.50
#
# "default via 192.168.1.1" = Tu puerta de enlace (router)
```

## Descargas e Interacción Web

### `wget` — Descargar Archivos

```bash
# Descargar un archivo:
wget https://ejemplo.com/archivo.zip

# Descargar con nombre personalizado (-O):
wget -O mi_archivo.zip https://ejemplo.com/archivo.zip

# Descargar en segundo plano (-b):
wget -b https://ejemplo.com/archivo_grande.iso

# Descargar un sitio web completo recursivamente:
wget -r -l 2 https://ejemplo.com
# -r = recursivo
# -l 2 = profundidad de 2 niveles

# Reanudar una descarga interrumpida (-c = continue):
wget -c https://ejemplo.com/archivo_grande.iso
```

### `curl` — Interactuar con URLs

`curl` es más versátil que `wget`. Además de descargar, puede enviar datos, hacer peticiones HTTP con diferentes métodos, etc.

```bash
# Ver el contenido de una página web:
curl https://ejemplo.com

# Descargar un archivo (-o = output):
curl -o archivo.zip https://ejemplo.com/archivo.zip

# Descargar siguiendo redirecciones (-L):
curl -L https://ejemplo.com/redirige

# Hacer una petición GET a una API:
curl https://api.ejemplo.com/usuarios

# Hacer una petición POST con datos:
curl -X POST -d "nombre=Juan&email=juan@mail.com" https://api.ejemplo.com/registro

# Enviar JSON a una API:
curl -X POST -H "Content-Type: application/json" \
  -d '{"nombre": "Juan", "email": "juan@mail.com"}' \
  https://api.ejemplo.com/usuarios

# Ver solo las cabeceras de respuesta (-I):
curl -I https://google.com
# HTTP/2 200
# content-type: text/html; charset=UTF-8
# date: Mon, 01 Sep 2026 10:30:00 GMT

# Modo silencioso (sin barra de progreso) (-s):
curl -s https://api.ejemplo.com/datos | grep "resultado"

# Verificar tu IP pública:
curl ifconfig.me
# 85.123.45.67
```

### Tabla Comparativa: `wget` vs `curl`

| Aspecto | `wget` | `curl` |
|---------|--------|--------|
| **Función principal** | Descargar archivos | Transferir datos (GET, POST, PUT, DELETE) |
| **Descarga recursiva** | ✅ Sí (`-r`) | ❌ No |
| **Reanudar descargas** | ✅ Sí (`-c`) | ✅ Sí (`-C -`) |
| **Protocolos** | HTTP, HTTPS, FTP | HTTP, HTTPS, FTP, SFTP, SCP, SMTP, y muchos más |
| **Interacción con APIs** | Básica | ✅ Completa (métodos, headers, auth) |
| **Salida por defecto** | Guarda en archivo | Muestra en pantalla (stdout) |
| **Uso típico** | Descargar archivos y sitios web | APIs, debugging web, transferencias |

## Configuración Manual de Red

### Cambiar la IP Temporalmente

```bash
# Cambiar la IP de una interfaz (temporalmente, se pierde al reiniciar):
sudo ifconfig eth0 192.168.1.100 netmask 255.255.255.0

# Con el comando ip (forma moderna):
sudo ip addr add 192.168.1.100/24 dev eth0

# Añadir una ruta por defecto (gateway):
sudo route add default gw 192.168.1.1
# o:
sudo ip route add default via 192.168.1.1

# Apagar una interfaz de red:
sudo ifconfig eth0 down
# o:
sudo ip link set eth0 down

# Encender una interfaz de red:
sudo ifconfig eth0 up
# o:
sudo ip link set eth0 up
```

> [!warning] Cambios temporales vs permanentes
> Los cambios con `ifconfig` o `ip` son **temporales**: se pierden al reiniciar. Para hacerlos permanentes, debes editar los archivos de configuración de red en `/etc/network/interfaces` (Debian/Ubuntu) o usar NetworkManager.

## Modos de Red en Máquinas Virtuales

Si usas VirtualBox, VMware o similares, entender los modos de red es crucial:

### NAT (Network Address Translation)

```
┌─────────────────────────────────────────┐
│  Tu PC (Host)          IP: 192.168.1.50 │
│  ┌─────────────────────────────────┐    │
│  │  VM (Guest)        IP: 10.0.2.15│    │
│  │                                  │    │
│  │  La VM sale a Internet a través  │    │
│  │  de la IP del HOST               │    │
│  │                                  │    │
│  │  VM → Host → Internet ✅         │    │
│  │  Internet → VM ❌ (no accesible) │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

### Bridged (Puente)

```
┌─────────────────────────────────────────────────┐
│  Red Local (192.168.1.0/24)                     │
│                                                  │
│  Router ──── Host (192.168.1.50)                │
│    │                                             │
│    └──── VM (192.168.1.51) ← ¡IP propia!       │
│                                                  │
│  La VM tiene su propia IP en la red local       │
│  VM ↔ Internet ✅                                │
│  VM ↔ Otros dispositivos de la red ✅           │
└─────────────────────────────────────────────────┘
```

| Modo | VM sale a Internet | Red local ve a la VM | IP de la VM | Uso típico |
|------|-------------------|---------------------|-------------|-----------|
| **NAT** | ✅ Sí | ❌ No | Red privada interna (10.0.2.x) | Navegación, actualizaciones |
| **Bridged** | ✅ Sí | ✅ Sí | IP real de la red local | Servidores, labs de red |
| **Host-only** | ❌ No | Solo el host | Red aislada (192.168.56.x) | Pruebas de red aisladas |
| **Internal** | ❌ No | ❌ No | Red entre VMs | Labs de redes entre VMs |

> [!tip] ¿Qué modo elegir?
> - **Para aprender Linux básico**: NAT es suficiente
> - **Para laboratorios de redes/ciberseguridad**: Usa Bridged o Internal
> - **Para servidores que necesitan ser accesibles**: Bridged
