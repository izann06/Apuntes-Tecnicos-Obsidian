# 🐧 ¿Qué es Linux? (Kernel vs Aplicaciones)

## La Historia: De un Proyecto Universitario a Dominar el Mundo

En 1991, un estudiante finlandés llamado **Linus Torvalds** publicó un mensaje en un foro de Internet que cambiaría la historia de la informática para siempre. Básicamente decía: *"Estoy haciendo un sistema operativo gratuito (solo un hobby, no será grande ni profesional como GNU)"*. Treinta y tantos años después, ese "hobby" se ejecuta en el **96.3% de los servidores del mundo**, en todos los supercomputadores del top 500 mundial, en cada teléfono Android, en la mayoría de dispositivos IoT, en el rover Perseverance de la NASA en Marte, y probablemente en tu router de casa.

> [!abstract] 🏠 Analogía: Linux es como el motor de un coche
> Piensa en Linux como el **motor** de un automóvil. Tú no interactúas directamente con el motor cuando conduces: usas el volante, los pedales y el tablero (las **aplicaciones**). Pero sin el motor, el coche no se mueve. Linux es ese motor invisible que hace que todo funcione por debajo, comunicándose directamente con el hardware (las ruedas, la transmisión, los frenos) para que tú puedas simplemente "conducir".

## Software Libre y Código Abierto: La Filosofía que lo Hizo Posible

Antes de entender Linux, necesitas entender la filosofía que lo creó: el **Software Libre** y el **Código Abierto** (Open Source).

### ¿Qué es el Software Libre?

El concepto de **Software Libre** fue acuñado por **Richard Stallman** en 1983 cuando fundó el proyecto **GNU** (GNU's Not Unix — sí, es un nombre recursivo y nerd a propósito). Stallman definió 4 libertades fundamentales:

| Libertad | Descripción | Analogía Cotidiana |
|----------|-------------|-------------------|
| **Libertad 0** | Ejecutar el programa como quieras, para cualquier propósito | Usar tu bicicleta para ir al trabajo, pasear o hacer deporte |
| **Libertad 1** | Estudiar cómo funciona el programa y modificarlo | Abrir el capó de tu coche y ver cómo funciona el motor |
| **Libertad 2** | Redistribuir copias para ayudar a otros | Fotocopiar una receta de cocina y regalarla a tus amigos |
| **Libertad 3** | Distribuir copias de tus versiones modificadas | Mejorar la receta, añadirle tu toque personal y compartirla |

> [!warning] Libre ≠ Gratis
> "Software Libre" se refiere a **libertad**, no a precio. En inglés se usa "Free as in freedom, not as in free beer" (Libre como en libertad de expresión, no como en cerveza gratis). Puedes cobrar por software libre, pero debes respetar las 4 libertades. Dicho esto, la inmensa mayoría del software libre es también gratuito.

### ¿Qué es el Código Abierto (Open Source)?

El **Open Source** es un enfoque más práctico y empresarial del mismo concepto. El código fuente del programa está disponible públicamente para que cualquiera lo lea, lo modifique y lo redistribuya. La diferencia con el Software Libre es más filosófica que práctica:

- **Software Libre** (Stallman/FSF): Enfoque **ético y moral**. Es un movimiento social.
- **Open Source** (OSI): Enfoque **pragmático y de negocio**. Es un modelo de desarrollo.

En la práctica diaria, la mayoría de la gente usa ambos términos de forma intercambiable. Linux es **ambas cosas**: Software Libre y Open Source.

### El Proyecto GNU: Las Herramientas sin Motor

Richard Stallman y la **Free Software Foundation (FSF)** crearon durante años un conjunto masivo de herramientas de software libre: compiladores (`gcc`), editores de texto (`emacs`), utilidades de terminal (`ls`, `cp`, `mv`, `grep`, `bash`), bibliotecas y mucho más. Todo lo que necesitas para un sistema operativo completo... **excepto el kernel** (el núcleo del sistema operativo).

Aquí es donde entra Linus Torvalds. Su "hobby" era exactamente eso: un **kernel**. Cuando el kernel de Linux se combinó con las herramientas GNU, nació un sistema operativo completo y funcional.

> [!tip] ¿Linux o GNU/Linux?
> Técnicamente, el nombre correcto del sistema operativo completo es **GNU/Linux**: las herramientas de GNU + el kernel de Linux. Pero en el uso cotidiano, todo el mundo dice simplemente "Linux". Stallman insiste en que se llame GNU/Linux para reconocer el trabajo del proyecto GNU. Linus Torvalds dice que le da igual. La comunidad usa "Linux" y ya. En estos apuntes usaremos **Linux** por simplicidad, pero ya sabes que en realidad es un trabajo en equipo.

## El Kernel: El Cerebro Invisible del Sistema

### ¿Qué es exactamente un Kernel?

El **Kernel** (núcleo) es el **corazón** del sistema operativo. Es el software más fundamental: el que se carga primero cuando enciendes el ordenador y el último que se apaga. Su trabajo principal es servir de **intermediario** entre el hardware (la máquina física) y el software (las aplicaciones que tú usas).

```
┌─────────────────────────────────────────────────┐
│            APLICACIONES DE USUARIO              │
│  (Firefox, VS Code, Terminal, Spotify, etc.)    │
│                                                 │
│  ┌───────────────────────────────────────────┐  │
│  │         ESPACIO DE USUARIO                │  │
│  │    (Las apps que tú ves y usas)           │  │
│  └───────────────────┬───────────────────────┘  │
│                      │ Llamadas al sistema       │
│                      │ (system calls)            │
│  ┌───────────────────▼───────────────────────┐  │
│  │            🧠 KERNEL DE LINUX             │  │
│  │                                           │  │
│  │  • Gestión de Procesos (qué se ejecuta)   │  │
│  │  • Gestión de Memoria (RAM)               │  │
│  │  • Drivers de Dispositivos (hardware)     │  │
│  │  • Sistema de Archivos (leer/escribir)    │  │
│  │  • Gestión de Red (paquetes, sockets)     │  │
│  │  • Seguridad (permisos, acceso)           │  │
│  └───────────────────┬───────────────────────┘  │
│                      │ Instrucciones directas    │
│  ┌───────────────────▼───────────────────────┐  │
│  │              HARDWARE                     │  │
│  │  (CPU, RAM, Disco, Red, USB, GPU, etc.)   │  │
│  └───────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

### Las 5 Responsabilidades Críticas del Kernel

| Responsabilidad | ¿Qué hace? | Ejemplo Real |
|----------------|------------|--------------|
| **Gestión de Procesos** | Decide qué programa se ejecuta, cuándo y cuánta CPU recibe | Cuando abres Firefox y Spotify a la vez, el kernel reparte el tiempo de CPU entre ambos |
| **Gestión de Memoria** | Asigna y libera RAM para cada proceso | Cuando abres una app, el kernel le reserva memoria. Cuando la cierras, la libera |
| **Drivers de Dispositivos** | Traduce las instrucciones de las apps a un lenguaje que el hardware entiende | Cuando imprimes un documento, el kernel habla con la impresora usando su driver |
| **Sistema de Archivos** | Organiza cómo se guardan y leen los datos en el disco | Cuando guardas un archivo en `/home/usuario/`, el kernel escribe los bits en el disco |
| **Gestión de Red** | Maneja las conexiones de red, paquetes TCP/IP, sockets | Cuando navegas por Internet, el kernel gestiona los paquetes de datos que entran y salen |

> [!tip] Comando para ver tu kernel
> Puedes ver qué versión del kernel de Linux tienes instalada con:
> ```bash
> uname -r
> # Ejemplo de salida: 6.1.0-23-amd64
> 
> # Para información más completa:
> uname -a
> # Linux mi-laptop 6.1.0-23-amd64 #1 SMP PREEMPT_DYNAMIC Debian 6.1.99-1 x86_64 GNU/Linux
> ```

### Espacio de Kernel vs Espacio de Usuario

El sistema operativo se divide en dos mundos separados por una barrera de seguridad:

- **Espacio de Kernel (Kernel Space)**: Aquí vive el kernel con acceso **total** al hardware. Solo el código del kernel puede hablar directamente con la CPU, la RAM y los dispositivos. Es la "zona VIP restringida".

- **Espacio de Usuario (User Space)**: Aquí viven **todas** tus aplicaciones: el navegador, la terminal, editores de texto, juegos, etc. Estas aplicaciones **no pueden tocar el hardware directamente**. Cuando necesitan hacerlo (escribir en disco, enviar datos por red, etc.), le piden permiso al kernel a través de unas funciones llamadas **system calls** (llamadas al sistema).

> [!abstract] 🏢 Analogía: El Hotel de Lujo
> Imagina un hotel de lujo:
> - **El Espacio de Usuario** son las habitaciones de los huéspedes. Cada huésped (aplicación) está en su propia habitación y no puede entrar a la de otro.
> - **El Espacio del Kernel** es la recepción, la cocina, la sala de máquinas y la administración. Los huéspedes no pueden entrar ahí directamente.
> - **Las System Calls** son el teléfono de la habitación. Si un huésped quiere pedir comida, llamar un taxi o que le suban toallas, llama a recepción (hace una system call) y el personal del hotel (el kernel) se encarga de todo.

## Las Distribuciones: Los "Sabores" de Linux

### ¿Qué es una Distribución (Distro)?

Una **distribución de Linux** (o "distro") es un sistema operativo completo que empaqueta:

1. El **Kernel de Linux** (siempre el mismo núcleo, puede variar la versión)
2. **Herramientas GNU** (utilidades de línea de comandos)
3. Un **gestor de paquetes** (para instalar software)
4. Un **entorno de escritorio** (la interfaz gráfica, si la tiene)
5. **Software preinstalado** seleccionado por los creadores de la distro
6. **Configuraciones y personalización** específicas

> [!question] ¿Existe "GNU/Linux" puro sin ninguna distro?
> Si GNU/Linux es el sistema operativo, ¿puedo descargar e instalar "GNU/Linux puro"? La respuesta es **no, al menos no con un solo instalador oficial**. 
> No existe un archivo llamado "GNU/Linux original". GNU/Linux es más bien una **combinación de componentes** (el kernel de Torvalds + las herramientas de Stallman). Para poder usarlo en la práctica, alguien tiene que juntar todas esas piezas dispersas, compilar el código, añadir un programa de instalación y verificar que todo funciona en armonía. **Ese sistema operativo ya ensamblado y listo para usar es lo que llamamos una Distribución (Distro)**. Toda distro es en realidad una versión de GNU/Linux.
> *(Nota: Si quieres hacerlo tú mismo pieza por pieza, existe un proyecto educativo llamado **Linux From Scratch (LFS)**, donde descargas el código fuente de todo y construyes tu propio GNU/Linux desde cero).*

> [!abstract] 🍦 Analogía: Los Sabores de Helado
> El kernel de Linux es como la **base de leche** de un helado. Todas las heladerías usan la misma base, pero cada una crea sabores diferentes añadiendo ingredientes distintos: chocolate, vainilla, fresa, menta... Cada "sabor" es una distribución diferente. El helado de chocolate (Ubuntu) y el de menta (Arch) saben completamente diferente, pero la base es la misma.

### Las Familias de Distribuciones

Las distros se organizan en "familias" basadas en la distro madre de la que derivan:

```

  (La abuela estable)  │                ├── Pop!_OS
                       │                ├── Elementary OS

                       ├── Kali Linux (Ciberseguridad)

> [!danger] ⚠️ Kali Linux NO es para principiantes
> Un error muy común de quienes empiezan en ciberseguridad es instalar Kali como su primera distro. Kali está diseñada como **herramienta de trabajo para profesionales de seguridad**, no como sistema operativo de escritorio diario. No incluye muchas comodidades que sí tiene Ubuntu o Mint. Aprende primero los fundamentos de Linux con Ubuntu o Debian, y después salta a Kali cuando entiendas qué estás haciendo.

### Los Gestores de Paquetes

Cada familia de distros tiene su propio **gestor de paquetes**, que es la herramienta para instalar, actualizar y eliminar software:

| Familia | Formato de paquete | Comando de instalación | Ejemplo |
|---------|-------------------|----------------------|---------|
| Debian/Ubuntu | `.deb` | `apt install` | `sudo apt install firefox` |
| Red Hat/Fedora | `.rpm` | `dnf install` | `sudo dnf install firefox` |
| Arch | `.pkg.tar.zst` | `pacman -S` | `sudo pacman -S firefox` |
| SUSE | `.rpm` | `zypper install` | `sudo zypper install firefox` |

> [!tip] ¿Qué distro elegir si eres principiante?
> Si estás empezando con Linux desde cero, la recomendación universal es **Ubuntu** o **Linux Mint**. Ambas son estables, tienen una comunidad enorme, documentación abundante en español, y casi todo "funciona de fábrica" sin tener que configurar nada manualmente.

## ¿Dónde se Usa Linux Hoy en Día?

Linux no solo vive en laptops de programadores. Está literalmente en todas partes:

| Área | Uso | Dato Curioso |
|------|-----|-------------|
| **Servidores Web** | Apache, Nginx, la nube de AWS/Azure/GCP | El 96.3% de los servidores del mundo usan Linux |
| **Teléfonos Móviles** | Android está basado en el kernel de Linux | Más de 3 mil millones de dispositivos Android activos |
| **Supercomputadores** | Los 500 supercomputadores más potentes del planeta | 100% usan Linux desde 2017 |
| **IoT y Embebidos** | Routers, smart TVs, refrigeradores inteligentes | Tu router WiFi probablemente ejecuta Linux |
| **Ciberseguridad** | Kali Linux, Parrot OS, herramientas de pentesting | Es el estándar de la industria de seguridad |
| **Automoción** | Tesla, Toyota, sistemas de infoentretenimiento | Automotive Grade Linux (AGL) |
| **Espacio** | El rover Perseverance de la NASA en Marte | Ejecuta Linux en el helicóptero Ingenuity |
| **Contenedores** | Docker, Kubernetes, microservicios | Los contenedores son literalmente procesos Linux aislados |
