# 🌳 El Árbol de Directorios y File System de Linux

## La Diferencia Fundamental: Un Solo Árbol vs Letras de Disco

Si vienes de Windows, estás acostumbrado a que cada disco duro, USB o partición tiene su propia **letra de unidad**: `C:\`, `D:\`, `E:\`, etc. Cada dispositivo es un "mundo" separado con su propia raíz.

En Linux, **todo** vive debajo de un **único punto de partida**: la barra oblicua `/`, llamada **raíz** (root). No importa si tienes un disco duro, tres particiones, un USB conectado o un disco de red compartido: todo se monta en algún punto dentro de ese árbol único.

> [!abstract] 🌳 Analogía: El Árbol Invertido
> Imagina un árbol real, pero al revés. La **raíz** `/` está arriba, y de ella crecen las ramas (directorios), que a su vez tienen más ramas (subdirectorios), y de esas ramas cuelgan las hojas (archivos). No importa cuántos discos o dispositivos conectes al sistema, todos se "injertan" en alguna rama de este único árbol.

### Comparativa Visual: Windows vs Linux

| Aspecto | Windows | Linux |
|---------|---------|-------|
| **Separador de rutas** | Barra invertida `\` | Barra normal `/` |
| **Raíz del sistema** | `C:\` (letra de unidad) | `/` (barra oblicua) |
| **Múltiples discos** | `D:\`, `E:\`, `F:\` | Se montan dentro del árbol: `/mnt/disco2`, `/media/usb` |
| **Carpeta del usuario** | `C:\Users\juan` | `/home/juan` |
| **Configuración del sistema** | Registro de Windows (`regedit`) | Archivos de texto plano en `/etc/` |
| **Programas instalados** | `C:\Program Files\` | `/usr/bin/`, `/usr/local/bin/`, `/opt/` |
| **Archivos temporales** | `C:\Users\juan\AppData\Local\Temp` | `/tmp/` |
| **Sensibilidad** | NO distingue mayúsculas: `Archivo.txt` = `archivo.txt` | SÍ distingue: `Archivo.txt` ≠ `archivo.txt` |

```
WINDOWS                          LINUX
═══════                          ═════
C:\                              /
├── Users\                       ├── home/
│   └── juan\                    │   └── juan/
├── Program Files\               ├── usr/
│   └── Firefox\                 │   └── bin/
├── Windows\                     ├── boot/
│   └── System32\                ├── etc/
D:\                              ├── mnt/
├── Juegos\                      │   └── disco2/    ← (D:\ equivalente)
E:\                              └── media/
└── USB\                             └── usb/       ← (E:\ equivalente)
```

## El FHS: La Constitución del Sistema de Archivos

El **Filesystem Hierarchy Standard (FHS)** es el estándar que define qué debe ir en cada directorio de un sistema Linux. Es como la **constitución** del sistema de archivos: establece las reglas que todas las distribuciones deben seguir para mantener la coherencia.

> [!tip] ¿Por qué importa esto?
> Gracias al FHS, si aprendes la estructura de directorios en Ubuntu, también la sabrás en Debian, Fedora, Arch o cualquier otra distro. Los archivos de configuración siempre estarán en `/etc`, los logs siempre en `/var/log`, los binarios del usuario siempre en `/usr/bin`, etc. Es un **lenguaje universal** entre todas las distribuciones.

```
├── dev/                   ← Dispositivos de hardware (virtuales)
├── etc/                   ← Configuraciones globales del sistema
├── home/                  ← Carpetas personales de los usuarios
│   ├── juan/
│   ├── maria/
│   └── pedro/
├── lib/                   ← Bibliotecas compartidas esenciales
├── lib64/                 ← Bibliotecas de 64 bits
├── media/                 ← Puntos de montaje automáticos (USB, CD)
├── mnt/                   ← Puntos de montaje manuales temporales
├── opt/                   ← Software opcional de terceros
├── proc/                  ← Info de procesos del kernel (virtual)
├── root/                  ← Carpeta personal del superusuario
├── run/                   ← Datos de ejecución volátiles
├── sbin/                  ← Binarios de administración del sistema
├── srv/                   ← Datos de servicios del servidor
├── sys/                   ← Información del kernel y hardware (virtual)
├── tmp/                   ← Archivos temporales
├── usr/                   ← Software y recursos del usuario
│   ├── bin/               ← Comandos de usuario
│   ├── lib/               ← Bibliotecas del usuario

│   └── share/             ← Archivos compartidos (docs, icons)

    ├── log/               ← Registros del sistema

    ├── tmp/               ← Temporales persistentes
    └── www/               ← Archivos del servidor web
        └── html/          ← Raíz de Apache/Nginx
```

## Guía Detallada de Cada Directorio

### `/` — La Raíz (Root)

La raíz es el **punto de partida absoluto** de todo el sistema de archivos. Todo directorio, archivo, dispositivo y recurso del sistema está contenido dentro de `/`. Es el equivalente a `C:\` en Windows, pero con la diferencia de que en Linux **solo hay una raíz** para todo.

```bash
# Ver el contenido de la raíz:
ls -l /
```

> [!danger] ⚠️ No confundir la raíz `/` con `/root`
> La barra `/` sola es la **raíz del sistema de archivos** (el directorio "padre de todos"). La carpeta `/root` es la **carpeta personal del superusuario** (el usuario root). Son cosas completamente distintas. Es como la diferencia entre "la entrada principal del edificio" (`/`) y "el despacho del director" (`/root`).

---

### `/bin` — Binarios Esenciales (Binary)

Aquí viven los **comandos fundamentales** que el sistema necesita para funcionar, incluso en modo de rescate o emergencia. Son los programas que **todos los usuarios** pueden ejecutar.

```bash
# Ejemplos de lo que vive en /bin:
ls /bin/
# bash, cat, cp, date, echo, grep, ls, mkdir, mv, rm, sh, touch...

# Verificar dónde vive un comando:
which ls
# /usr/bin/ls  (en distros modernas, /bin es un enlace a /usr/bin)
```

> [!tip] Dato moderno
> En distribuciones recientes (Ubuntu 20.04+, Fedora, Arch), `/bin` es en realidad un **enlace simbólico** a `/usr/bin`. La separación histórica entre `/bin` y `/usr/bin` ya no es necesaria, pero se mantiene el enlace por compatibilidad. Cuando haces `ls /bin`, en realidad estás viendo `/usr/bin`.

---

### `/boot` — Archivos de Arranque

Contiene todo lo necesario para que el sistema **encienda y arranque**: el kernel de Linux compilado, la imagen initramfs (el mini sistema que se carga antes del sistema real) y la configuración del bootloader (GRUB).

```bash
ls /boot/
# grub/                    ← Configuración del bootloader GRUB
# vmlinuz-6.1.0-23-amd64   ← El kernel de Linux comprimido
# initrd.img-6.1.0-23      ← Imagen de disco RAM inicial
# config-6.1.0-23-amd64    ← Configuración con la que se compiló el kernel
```

> [!danger] ⚠️ Zona de Peligro
> **Nunca** elimines archivos de `/boot` manualmente a menos que sepas exactamente lo que estás haciendo. Borrar el kernel o la configuración de GRUB puede hacer que tu sistema **no arranque** la próxima vez que reinicies.

---

### `/dev` — Dispositivos (Devices)

En Linux, **todo es un archivo**, incluso el hardware. El directorio `/dev` contiene archivos especiales que representan dispositivos de hardware. No son archivos normales con datos dentro: son **interfaces** que el kernel usa para comunicarse con el hardware.

```bash
ls /dev/
# sda        ← Primer disco duro (SATA/SCSI)
# sda1       ← Primera partición del primer disco
# sda2       ← Segunda partición del primer disco
# sdb        ← Segundo disco (o USB)
# nvme0n1    ← Disco NVMe (SSD moderno)
# tty0       ← Terminal virtual
# null       ← El "agujero negro" de datos
# zero       ← Fuente infinita de ceros
# random     ← Generador de números aleatorios
# urandom    ← Generador de números aleatorios (no bloqueante)
```

> [!abstract] 🕳️ El Sifón Devorador de Datos: `/dev/null`
> `/dev/null` es un archivo especial que actúa como un **agujero negro**: todo lo que le envías desaparece para siempre. No se guarda, no se procesa, simplemente se destruye. Es extremadamente útil cuando quieres ejecutar un comando pero **no te interesa ver su salida** o sus errores:
> 
> ```bash
> # Ejecutar un comando descartando toda la salida:
> comando_ruidoso > /dev/null 2>&1
> 
> # Descartar solo los errores:
> find / -name "archivo.txt" 2>/dev/null
> ```
> 
> Su primo `/dev/zero` es lo contrario: una fuente **infinita de bytes cero** que nunca se acaba. Se usa para crear archivos de un tamaño específico llenos de ceros o para borrar datos de forma segura.

---

### `/etc` — Configuraciones del Sistema (Etcetera)

El **cerebro administrativo** del sistema. Aquí se guardan **todos** los archivos de configuración global del sistema en **texto plano**. A diferencia de Windows (que esconde todo en el Registro), Linux guarda sus configuraciones en archivos que puedes leer y editar con cualquier editor de texto.

```bash
ls /etc/
# Algunos archivos importantes:
# passwd        ← Lista de usuarios del sistema
# shadow        ← Contraseñas cifradas de los usuarios
# group         ← Lista de grupos del sistema
# hostname      ← Nombre del equipo
# hosts         ← Resolución de nombres local (como un mini DNS)
# fstab         ← Tabla de montaje de sistemas de archivos
# sudoers       ← Quién puede usar sudo
# crontab       ← Tareas programadas del sistema
# ssh/          ← Configuración del servidor SSH
# apache2/      ← Configuración del servidor web Apache
# nginx/        ← Configuración del servidor web Nginx
# network/      ← Configuración de interfaces de red
# apt/          ← Configuración del gestor de paquetes apt
```

> [!tip] Archivos de configuración que usarás constantemente
> Como administrador de sistemas, vivirás editando archivos en `/etc`. Los más importantes para empezar son:
> - `/etc/passwd` — Ver usuarios del sistema → [[03.4 - Administración de Usuarios, Grupos y Propiedades]]
> - `/etc/hosts` — Resolver nombres de dominio localmente
> - `/etc/fstab` — Configurar montaje automático de discos
> - `/etc/sudoers` — Configurar privilegios de sudo → [[03.4 - Administración de Usuarios, Grupos y Propiedades]]

---

### `/home` — Hogares de los Usuarios

Cada usuario normal del sistema tiene su propia carpeta personal dentro de `/home`. Es el equivalente a `C:\Users\` en Windows. Aquí guardan sus documentos, descargas, configuraciones personales, etc.

```bash
ls /home/
# juan/
# maria/
# pedro/

# Tu carpeta home siempre es accesible con ~
cd ~
# Es equivalente a:
cd /home/tu_usuario

# Ver archivos ocultos de configuración personal:
ls -la ~/
# .bashrc      ← Configuración de tu terminal Bash
# .profile     ← Variables de entorno del perfil
# .ssh/        ← Claves SSH personales
# .config/     ← Configuraciones de aplicaciones
# Documentos/
# Descargas/
# Escritorio/
```

> [!tip] La virgulilla `~` (colita de chancho)
> El carácter `~` es un atajo universal que siempre apunta a tu carpeta home. No importa en qué directorio estés, `cd ~` te lleva a casa. Esto se explora en detalle en [[01.3 - Rutas Absolutas vs Relativas]].

---

### `/lib` y `/lib64` — Bibliotecas Compartidas (Libraries)

Las **bibliotecas** (o librerías) son fragmentos de código que muchos programas comparten. En vez de que cada programa incluya su propia copia de funciones comunes, todos usan las mismas bibliotecas compartidas desde `/lib`.

```bash
# Ver bibliotecas compartidas:
ls /lib/x86_64-linux-gnu/
# libc.so.6      ← La biblioteca C estándar (la más fundamental)
# libpthread.so  ← Biblioteca de hilos (threads)
# libm.so        ← Biblioteca de funciones matemáticas

# Ver qué bibliotecas usa un programa:
ldd /usr/bin/ls
# linux-vdso.so.1
# libselinux.so.1 => /lib/x86_64-linux-gnu/libselinux.so.1
# libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6
```

> [!abstract] 📚 Analogía: La Biblioteca Pública
> Imagina que `/lib` es una **biblioteca pública** de la ciudad. En vez de que cada casa (programa) compre sus propios libros (código), todos los vecinos van a la biblioteca a consultar los mismos ejemplares. Esto ahorra espacio y evita duplicaciones. Si la biblioteca actualiza un libro (una vulnerabilidad de seguridad parcheada), todos los vecinos se benefician automáticamente.

---

### `/media` — Montaje Automático de Dispositivos Extraíbles

Cuando conectas un **USB**, insertas un **CD/DVD** o montas una tarjeta SD, el sistema automáticamente los hace accesibles dentro de `/media/tu_usuario/`.

```bash
# Conectar un USB llamado "MI_USB":
ls /media/juan/
# MI_USB/

# Acceder al contenido del USB:
cd /media/juan/MI_USB/
ls
# fotos/  documentos/  musica/
```

---

### `/mnt` — Montaje Manual Temporal

Similar a `/media`, pero pensado para montajes **manuales y temporales** realizados por el administrador del sistema. Es donde montas particiones adicionales, discos de red o sistemas de archivos remotos.

```bash
# Montar manualmente una partición:
sudo mount /dev/sdb1 /mnt/disco_externo

# Montar un recurso compartido de red (NFS):
sudo mount -t nfs servidor:/compartido /mnt/red

# Ver qué está montado:
mount | grep /mnt

# Desmontar cuando termines:
sudo umount /mnt/disco_externo
```

---

### `/opt` — Software Opcional (Optional)

Directorio reservado para software de **terceros** que no forma parte de la distribución estándar. Muchas empresas instalan sus aplicaciones aquí: Google Chrome, Zoom, herramientas propietarias, etc.

```bash
ls /opt/
# google/chrome/        ← Google Chrome
# visual-studio-code/   ← VS Code (si se instala desde el .deb oficial)
# lampp/                ← XAMPP (stack Apache, MySQL, PHP)
```

---

### `/proc` — Información de Procesos (Process)

Un sistema de archivos **virtual** (no ocupa espacio en disco). El kernel genera dinámicamente su contenido para mostrarte información en tiempo real sobre los procesos en ejecución y el estado del sistema.

```bash
# Ver información de la CPU:
cat /proc/cpuinfo

# Ver información de la memoria RAM:
cat /proc/meminfo

# Ver información de un proceso específico (PID 1234):
ls /proc/1234/
# cmdline  cwd  environ  exe  fd  maps  status ...

# Ver el tiempo que lleva encendido el sistema:
cat /proc/uptime
# 123456.78 234567.89
```

---

### `/root` — Hogar del Superusuario

La carpeta personal del usuario **root** (el administrador supremo del sistema). Está separada de `/home` porque en situaciones de emergencia, la partición `/home` podría no estar disponible, pero root siempre necesita poder iniciar sesión.

```bash
# Solo root puede acceder:
sudo ls /root/
# .bashrc  .profile  .ssh/
```

> [!warning] El usuario root
> `root` es el **superusuario** de Linux. Tiene permisos para hacer absolutamente todo: crear usuarios, borrar el sistema entero, modificar archivos del kernel, etc. Por seguridad, **nunca debes trabajar como root en el día a día**. Usa `sudo` cuando necesites privilegios temporales. Más sobre esto en [[03.4 - Administración de Usuarios, Grupos y Propiedades]].

---

### `/sbin` — Binarios del Sistema (System Binary)

Comandos de **administración del sistema** que normalmente solo usa root o con `sudo`: herramientas de red, gestión de discos, inicio/apagado del sistema, etc.

```bash
ls /sbin/
# fdisk        ← Gestión de particiones
# iptables     ← Firewall
# ifconfig     ← Configuración de red
# reboot       ← Reiniciar el sistema
# shutdown     ← Apagar el sistema
# mount        ← Montar sistemas de archivos
```

---

### `/tmp` — Archivos Temporales (Temporary)

Espacio para archivos temporales que **cualquier usuario o programa** puede crear. Su contenido se borra automáticamente al reiniciar el sistema (en la mayoría de distros).

```bash
# Crear un archivo temporal:
touch /tmp/mi_archivo_temporal.txt

# Listar archivos temporales:
ls /tmp/
```

> [!tip] El Sticky Bit de `/tmp`
> El directorio `/tmp` tiene un permiso especial llamado **Sticky Bit** que permite a cualquier usuario crear archivos, pero **solo el propietario** de cada archivo puede borrarlo. Esto evita que un usuario malicioso borre los archivos temporales de otro. Se explica en detalle en [[03.3 - Seguridad por Defecto (UMask y Permisos Especiales)]].

---

### `/usr` — Recursos del Usuario (Unix System Resources)

El directorio más **grande** del sistema. Contiene la mayoría del software instalado, bibliotecas, documentación y recursos compartidos. Piensa en `/usr` como el "segundo nivel" de programas: los que no son estrictamente necesarios para que el sistema arranque, pero sí para que funcione con normalidad.

```bash
ls /usr/
# bin/       ← Comandos de usuario (la mayoría de los que usas)
# lib/       ← Bibliotecas
# local/     ← Software instalado manualmente (compilado desde fuente)
# share/     ← Archivos compartidos (documentación, iconos, fondos)
# sbin/      ← Comandos de administración no esenciales
# include/   ← Cabeceras de C/C++ para desarrollo
# src/       ← Código fuente del kernel (si se instala)
```

---

### `/var` — Archivos Variables (Variable)

Contiene archivos cuyo contenido **cambia constantemente** durante la operación normal del sistema: logs del sistema, caché de paquetes, colas de impresión, archivos del servidor web, bases de datos, etc.

```bash
# Los subdirectorios más importantes de /var:
ls /var/
# log/       ← Registros del sistema (¡fundamental para debugging!)
# cache/     ← Caché de aplicaciones y paquetes
# tmp/       ← Temporales que persisten entre reinicios
# mail/      ← Buzones de correo del sistema
# spool/     ← Colas (impresión, correo saliente)
# www/       ← Archivos del servidor web
#   └── html/  ← Raíz predeterminada de Apache/Nginx

# Ver logs del sistema en tiempo real:
sudo tail -f /var/log/syslog

# Ver logs de autenticación (intentos de login):
sudo tail -f /var/log/auth.log

# Ver logs del kernel:
sudo dmesg | tail -20
```

> [!tip] `/var/log` es tu mejor amigo como sysadmin
> Cuando algo falla en un servidor Linux, lo primero que haces como administrador de sistemas es revisar los logs en `/var/log/`. Aquí encontrarás pistas de todo lo que sucede: errores de aplicaciones, intentos de acceso no autorizados, fallos de hardware, problemas de red, etc. El comando `tail -f` te permite ver los logs en **tiempo real**, como se explica en [[04.1 - Redirecciones, Pipes y Filtros de Texto]].

> [!tip] `/var/www/html` para servidores web
> Si instalas Apache o Nginx, los archivos de tu sitio web van por defecto en `/var/www/html/`. Cuando accedes a `http://localhost` en tu navegador, el servidor web sirve los archivos de esta carpeta.
